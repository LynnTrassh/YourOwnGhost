# 随机房间与内容编排

版本：v0.1；日期：2026-10-30。依据 [GDD](game-design-v0.2.md) 第 7–11 节。本文定义完整生成目标与失败处理。当前每层总计 8–12 房，已接入两层独立布局、固定卧室、11 种九宫格轮廓、四类内部布局、通行校验和保底；已识别环路、分叉、死路与出口路线，并接入猫群、左右建议和第二层凝视雕像的局部适配。完整剧情组合、配对视听、跨层物件依赖与动态空间尚未实现。

## 1. 生成目标与计数

先按 PCG 规则生成空间和门连接，再识别结构机会，匹配满足条件的剧情。内容规则约束数量、适配、互斥与因果，不预排一条固定剧情路线。单局以 4–6 个主要剧本为节奏目标；一条剧本可能跨多个房间，57 项内容不是 57 个房间。

计数使用 narrativeUnitId：B13–B16 合并为一个追逐单元；B26 与主流程共用卧室单元，不重复计算；B27／B28 是相应前置剧本的跨层尾声。技术布局可以增加连接房和安静路段，但不得用房间数量冒充实际体验时长。

内容来源、短场面预算与覆盖诊断见 [剧情分池与探索内容编排](content-scheduling.md)。先匹配输入资格与可用能力，再在实际结构机会中选主要单元，并用自带短场面、配对支持段及真正喘息空间补足探索。每层统计非卧室房间覆盖和各条向前路线的纯连接房间隔；覆盖与间隔是调试评分，不能压过语义、通行和事件因果硬约束。当前未实现这些完整统计与抽取规则。

确定性输入为 seed、已确认的偏好解释、contentVersion、rulesVersion、已确认内容计划。保存 planHash 与完整规划结果。AI 的重复调用不保证同结果，所以已经确认的计划不得在重进或死亡时重新请求；布局、装饰、声音变体使用独立随机子流，增加一个摆件不应改变地图拓扑。

## 2. 数据契约

| 数据 | 核心字段 |
|---|---|
| ContentPlan | planId、inputRevision、selectedUnits、dependencyEdges、exclusions、layerAssignments |
| RoomTemplate | templateId、轮廓／房型标签、允许尺寸范围、门槽、窗槽、入口落点、观察点、通行区域、内容落点、遮挡区域、承重与碰撞壳体 |
| Slot | slotId、roomId、局部变换、用途标签、允许包围盒、观察方向、占用互斥组 |
| SpatialRequirements | 节奏顺序、剧本实例关系、主路／分支、回访环、配对视听、追逐链、跨层前置与预留槽要求 |
| RoomLayout | templateBindings、房间变换与尺寸、配对门槽、几何边界、预留通道及空间检测结果 |
| RoomGraph | rooms、edges、start、exit、graphVersion、chasePaths、returnLoops |
| ScriptPlacement | instanceId、definitionId、roomBindings、objectBindings、observationVolumes、audioLinks |
| LayerPlan | graph、placements、reservedEchoSlots、assetBindings、validationReport |

门槽包含墙面、宽高、内外安全落点及是否双向；不以数组顺序代表方向。槽位允许范围与可通行范围分别定义，桌上摆件不能占用走道落点。窗、观察窗、镜面和监控是不同用途，不能仅按“有一个矩形面”互换。

模板可以随机改变允许范围内的尺寸与装饰，但关键构图、镜面角度、逃生宽度和群体视线属于硬约束。资产到位后按实际包围盒复验，不能只根据文件名假定不会挡门。

## 3. 生成流水线

管线归属 [技术框架的 planning 模块](technical-architecture.md#随机地图管线在架构中的位置)。输入是已确认偏好、种子、内容／规则版本和可用资源能力；输出是通过校验的纯数据计划及报告。以下阶段为目标接口，不代表已经存在对应代码。

| 阶段 | 输入 | 处理 | 输出与阶段检查 |
|---|---|---|---|
| 1 解释与确认 | 喜欢／害怕输入、玩家修正 | 语义服务或本地映射形成素材解释，玩家确认；区分真实生成与预设模式 | 固定的偏好解释及 inputRevision；不支持的输入提供兼容预设，不静默误解 |
| 2 空间生长 | 种子、固定卧室、11 种房型库 | 在九宫格外框上紧凑拼接兼容轮廓与朝向，以共墙门连通，随机增加合法邻接门 | RoomLayout 与 RoomGraph；不指定猫房、左右房或回访路线 |
| 3 结构识别 | 实际房间连接图、门位与通行数据 | 找出环路、分叉、死路及可用路线，再检查观察点、遮挡、方向与追逐净空 | 空间机会集合；图结构候选不等于剧情可用，当前只实现图结构识别 |
| 4 内容匹配 | 确认偏好、空间机会、剧本能力 | 根据条件匹配场面，形成 4–6 个主要单元的目标组合；没有机会不虚构场面 | ContentPlan 初稿与绑定候选；此阶段尚未接入运行实现 |
| 5 依赖与节奏 | 候选组合、互斥与前置规则 | 验证事实依赖、两层对应、内容数量和节奏；不合格时换组合或确定性重生成 | 内容与空间共同满足约束，不强制玩家按预设顺序游览 |
| 6 内容落位 | 布局、槽位、剧本定义、资产能力 | 放置对象、家具、怪物、灯光与声源；绑定观察焦点、事件、旁白及状态实例 | ScriptPlacement 与 LayerPlan 候选；角色、物件和台词以稳定 ID 关联 |
| 7 校验与重试 | 完整候选、碰撞和状态变化规则 | 先校验硬约束，再计算软评分；失败按确定性尝试序列重建候选 | ValidationReport；未通过不得进入提交阶段，超限走第 8 节保底规则 |
| 8 提交与实例化 | 通过校验的计划、当前会话与转场标识 | flow 确认会话仍有效，由 state 一次写入图、位置、实例和版本 | 已提交梦层；新局、假醒和死亡使用不同初始化策略 |
| 9 表现加载 | 已提交计划、资源绑定 | presentation 构建 Three.js 场景；assets 加载或替换兼容占位资源 | 可呈现的场景；加载不重新抽图，进场前确认必需碰撞和内容表现就绪 |

生成器不直接创建 Three.js 对象。失败报告至少携带阶段、错误码、关联 roomId／instanceId、attemptIndex 和是否使用保底。流程只接受成功计划或明确失败，不读取候选中间状态作为正在游玩的世界。

### 房型选择与空间嵌入

轮廓严格使用第 13 节已确定的 11 种掩码，不因剧情需要产生新轮廓。每模块 5×5 米，完整外框 15×15 米；多出口是开门属性。出生卧室固定，其余房间选择兼容的轮廓、朝向与贴合位置，实际共墙处才能开门。

当前总房数由种子在 8–12 间中选择，这是空间调试规模，不是剧情数量。每个新增房间接到已生成空间保证可达，其他共墙关系按种子决定是否开门；由此自然形成不同连接图。出口选择生成图中离卧室门数距离最远的可达房间，其路径是诊断信息，不是强制主线。

### 从空间机会到剧情的例子

CAT01 可匹配具有合理回访机会、足够容纳空间和观察条件的房间。当前先检测环路中具有中央空间的候选并预留落点，再检查可达观察点与群体视线，通过后才启用 CAT01。没有环路候选就不强行造出“猫房”；后续也可识别合适的支路回程机会。

运行时仍必须满足“玩家看见初始场面 → 正常离开 → 再次返回”等事件条件。玩家没回来就不触发回访变化，旁白不能假定事件发生。路线建议同样先寻找合适的实际分叉，再验证抵达方向、左右门位与建议可见性；图中度数不少于 3 只表示分叉候选，不直接等于左右选择剧情。

先锁定通过验证的内容落点与通行区域，再生成家具。摆放完成后复验空间、视线和事件条件。普通死亡保持已提交地图和已发生事实，不重抽拓扑。

### 资源与生成的时序

开局优先用已验证的资源能力和占位包围盒确定空间。模型任务完成后，按实际尺寸、朝向、材质与动画能力复验，再绑定到原 placement。模型生成时间不决定房间编号、门连接或已发生的剧情。

表现加载失败使用同一 placement 的兼容占位资源；最终模型不符合槽位时保留占位，不把它强塞进通道。若必需表现和占位都不可用，在玩家进场前返回失败或选择通过相同校验的保底计划。开始探索后不能因某个模型加载失败而重新随机整层。

## 4. 各类空间关系

| 组合 | 硬约束与验收 |
|---|---|
| C01 独立房 | 入口可见关键构图或可自然走到观察点，出口不被表现占用 |
| C02 回访房 | 有可执行的正常路线先经过初始状态、离开、再经过同一对象；不是仅数学上可以掉头 |
| C03 配对房 | 观察窗／门缝／声音连接真实成立，相关房间状态一致；窗后房不能在玩家进入时无故重新初始化 |
| C04 连续房组 | 威胁与玩家共享合法路径；跨门不删除威胁；临时关门和隐藏均有声明规则 |
| C05 跨层呼应 | 存在前置内容和预留槽，切层时检查真实观察事实后启用 |

猫房回访放在自然探索短环：卧室 → 猫房初见 → 分支空间 → 猫房另一入口／回程 → 向出口推进。不可用文字任务命令回头，也不能要求玩家完成观察才解锁出口；没看见可以错过表达，不能堵住通关。

## 5. 路线建议与偏离

在安全探索区布置左右均可见的分叉，两条路线均可通行并汇合到后续主路线。具体场面由兼容内容分配，分叉不把核心前置关系切断。首次实现采用两条短支路汇合，确保右路不因“不服从”受到额外惩罚。

RouteSuggestion 绑定 forkId、leftDoorId、rightDoorId、suggestionId 与出口区域。只有建议完成有效呈现后选择右路才生成偏离事实；未听见建议、直接绕过或先右转后播放建议都不成立。左右是建议发生时的门方位，转身后不重新解释。进入支路只记录一次选择，往返刷门不能刷评论。

两条路线不要求完全相同，但危险规则不得因偏离建议临时改变。两条分支各自验证可达出口、必需回访与跨层前置，不依赖旁白引路才能通关。

## 6. 两层计划与实际经历

开局生成第一层及第二层的空间骨架，预留呼应槽；语义与剧本选择结果固定。第一层结束时冻结可跨层事实快照，再实例化第二层条件内容。

| 内容 | 必须存在的事实 | 未发生时处理 |
|---|---|---|
| IN04 | 玩家确实观察源痕迹，并符合所选传播阶段 | 保留正常空间，不出现无依据痕迹或相关台词 |
| B27 | 玩家观察 B03 枯黑结果 | 使用正常床边装饰，不出现“恢复”事件或评论 |
| B28 | 玩家观察 B04 破损结果 | 床边不出现该玩偶，不评论“放近一点” |

选择前置剧本不等于玩家看见它。条件结果未启用时不临时抽另一个强烈事件，也不强迫补看。第二层启用决定记录在计划实例中；第二层死亡不重新计算前置或重新抽取。

## 7. 追逐布局与动态空间

B13–B16 使用完整模板链：侧门预警区 → 可关门延缓的过渡房 → 两条连通路径的杂物间 → 带遮挡点的侧室及怪物经过走廊。安全示范、怪物冲出位置和玩家反应距离必须成立。侧室隐藏点不是画面看不见就算隐藏，需通过怪物视线与路径检测；暴露后可以重新追逐。

临时门延缓属于追逐状态，死亡后复位；永久剧情变化保留。怪物不能出生在玩家落点内，也不能因关门直接永久失去路径。宽限时间、速度、开门延缓与安全距离通过配置集中调试，记录目标设备试玩结果。

B17 改门连接、B20 移除门走图事务；B19 倾斜与 BO03 呼吸先验证表现包络不侵入通道。每个动态变化必须验证发生前后和合法变化组合，不只验证初始布局。失败时保留原图，取消依赖该变化结果的台词。

## 8. 校验、重试与保底

硬约束：ID 唯一、引用存在、门槽不冲突、门两侧落点安全、角色半径可通过、起点到出口可达、必需关系成立、关键焦点可观察、追逐路径有效、前置与互斥正确、资产能力满足、动态变化后仍合法。

可达性包含拓扑与实际碰撞两层：图上连通不等于家具之间可走。对占位及最终资源包围盒检查通行栅格／导航区域；对状态变化按允许状态组合验证。验证器输出错误码和关联 roomId／instanceId，不只返回 false。

软约束：重复主题间隔、强弱节奏、视听焦点冲突、路线长度、昂贵效果数量。软评分不能抵消硬失败。十分钟是试玩目标，路径长度与预估演出时长仅用于筛选，不作为达标证据。

首次实现给每个输入最多 20 次确定性尝试，attemptIndex 派生子种子并写入报告。这是可调初始值，不是已验证的性能上限。重试保留已确认的偏好与硬约束，可重新匹配尚未提交的内容组合、模板、布局和落点，不重新调用语义服务或悄悄替换玩家已确认的内容。超限优先选择兼容当前 ContentPlan 的已验证保底布局；若只能使用同偏好类别的保底内容计划，必须在进场前明确告知使用保底方案，生成新的计划标识并完整校验。完整内容保底仍需满足核心流程及内容约束；当前空间灰盒保底仅保证可达、封闭边界和结构数据真实，不虚构回访或追逐事件。保底布局亦须通过相同校验，不允许跳过校验强行开局；如资源损坏导致保底也无效，显示可重试错误，不把玩家放入不可通关地图。

## 9. 测试与诊断

固定种子测试覆盖两层、猫／花语义、全套关系与互斥；每个剧本至少在一个合法布局演示。批量生成用代表性种子集和边界输入，记录失败率、原因、重试次数和保底使用；通过一组种子不意味着任意输入都已证明合法。

必须额外检查：死亡不重抽、装饰子流不改变拓扑、同版本同输入复现、改变内容版本能识别不兼容、未见前置无跨层结果、左右分支均通关、追逐不因卸载中断、门变化失败可回滚。

调试视图显示房间图、门槽、观察体积、回访环、追逐路径、事实依赖、资产占用及失效原因。支持导出 planHash、完整纯数据计划与事件日志供本地复现；导出不包含密钥。真人试玩分别验证方向感、自然回访、恐怖节奏和无旁白通关。


## 12. 房间内部布局与装饰

房间生成分为四层：外轮廓 → 门口位置 → 内部布局 → 装饰细节。相同外轮廓与门位允许绑定不同内部布局，书架、柜台等结构参与动线和视线组织；颜色、书本排列等只作为外观变化。布局随机子流与外壳、装饰分开，替换装饰不得改变碰撞或通行关系。

| 布局 | 空间作用 | 当前灰盒表现 |
|---|---|---|
| 中央绕行 | 中部实体迫使玩家选择两侧路线 | 偏离中心锚点的低柜台组合 |
| 留白空间 | 保留开阔通行与观察空间 | 不生成独立内装障碍 |
| 交错柜体 | 交替阻挡通行，产生曲折路线 | 中央柜台与边界处靠墙书架 |
| 沿墙陈设 | 物件靠外围，保留较开阔的中央区域 | 外围书架组合 |

当前模板根据可用网格、旋转和门位裁剪；布局名称表示生成意图，不保证每个小房间都有完整组合。无法保持内部连通的家具候选会被跳过。没有足够可用位置时允许减少家具，不以堵路换取密度。

当前实现保护房间中心、出生点、门口内外网格、床和猫房内容落点。每件新增家具保守占用一个网格，剩余网格必须在房间内部连通；随后基于墙体及家具碰撞体建立通行图，验证所有门口、房间中心、出口、双分支及回访所需连接。渲染、移动碰撞和调试地图读取同一份障碍数据，不在加载场景时再次随机摆放。

布局种子支持生成器参数 interiorSeed，默认继承地图 seed，用于固定外壳时单独验证内装变化；菜单仍只提供统一地图种子。同一种子在同一生成版本下可复现，生成规则升级后不承诺复现旧版地图。

后续剧本适配需要声明观察视锥、遮挡高度、逃跑通道宽度、追逐绕行和演出空间；当前只实现基础可达性与内容落点保护，尚未实现自动视线构图验收或完整追逐约束。柜台和书架仍是程序化灰盒资产，密度、尺度与绕行节奏需真人试玩调整。


## 13. 九宫格轮廓规则

房间以一个大正方形为边界，划分成 3×3 空间模块，选取连通的模块组成轮廓。模块不是独立房间，相邻占用模块之间默认连通，不自动生成内墙或门；当前内装层不生成独立隔断。多出口是连接属性，不单列为轮廓。

当前模板如下，1 表示房间空间，0 表示未占用区域；允许整体旋转：

| 轮廓 | 由上到下三行 |

## 14. 固定出生卧室

出生卧室不参与随机外壳、内装与装饰抽取，沿用当前 seed 42 的 T 形、旋转 180 度、中央绕行内装样式。轮廓、门口、窗面、床、柜台、墙面色调、灯光与出生位置／朝向保持一致，成为每局稳定的起点。固定入口朝向，门外房间轮廓与后续布局继续由种子决定；保底地图也使用相同卧室。

本规则仅约束开局生成，不取消剧本明确要求的卧室状态变化或假醒演出。普通死亡和重开仍遵循各自的状态保留规则。


## 15. 房间直接贴合

九宫格房间按 15 米外框紧挨排列，不再在房间之间额外预留间距或生成连接走廊。先根据所需连接方向筛选轮廓与朝向，再与已放置房间匹配共用边界，每条既定连接仅开一个门洞。无法直接接上的组合不采用，不以长短走廊补接。

门洞只允许位于完整 15×15 米九宫格外框四条边的中点，即相对外框中心的 (±7.5, 0) 或 (0, ±7.5) 米，每边最多一扇门。以九宫格外框中心定位，不使用 L 形或回字形的内容锚点；不选择两侧模块的边中点，也不向凹口内缩。轮廓没有覆盖该方向中间模块时，该方向不可连接，不能补格或改变既定轮廓。生成时先检查父房门位，再选择相对门位同样存在的邻房轮廓和朝向；附加环路门遵守相同规则。

门洞宽度保持 1.6 米，两侧房间共享同一门位。固定出生卧室仍使用北侧外框中点门。生成校验同时核对两侧房间外框中点、门坐标与相邻通行格；即使侧边模块中点物理可通行，也会作为非法门位拒绝。

物理相邻不等于逻辑连通：未列入关系图的相邻房间保持完整隔墙，防止额外捷径绕过分支与回访。固定卧室保持原门口、出生位置和内装；门外直接进入下一间房。全部 11 种轮廓仍可在兼容位置使用，回字形的中心保持空缺。


房间边界必须连续封闭，只有明确登记的门洞可以留口。外墙、共用墙、凹口及回字形内圈均生成实体墙与碰撞；九宫格模块之间属于同一房间的内部接缝不额外砌墙。生成校验逐段检查边界的完整覆盖，墙段缺失时拒绝计划。调试平面图读取同一份墙体数据，浅色连续线表示墙，橙色短线表示门洞。


## 16. 空间机会数据与实现边界

plan.opportunities 包含 cycles（去重后的环路候选，并非枚举所有简单环）、forks（房间及邻居）、deadEnds（非卧室单门房）、revisitCandidates（环路中有中央空间的房间）、branchReturnRoutes／branchReturnCandidates（从分叉探入非出口死路后必然再次经过的中途房间）、exitRoute（到所选出口的最短房间序列）。这些数据从实际边重建并校验，不由固定房间名称推断。支路候选排除出口所在支路、端点、环路与无中央空间的房间；回访场面可在两类真实回程机会中落位，猫房仍仅使用已预留的环路候选。场面触发依旧需要玩家实际观察、正常离开与返回，空间机会不等于玩家已回访。

当前未实现汇合点／瓶颈分析、完整镜头构图、追逐路线净空、完整剧情组合或动态变化后的全面剧情复验。空间图可达不作为这些功能的验收证据。

## 17. 首轮空间适配与剧情灰盒

在拓扑、墙体和内装确定后，`plan.story` 记录实际接纳的猫房、左右建议入口及拒绝原因。适配器只读取空间，不修改房型、连接图或出口路线；没有适配场景仍是合法地图。当前仅尝试已预留的首个回访候选，不代表全部可用房间搜索。 `reserved.cat` 只描述预留空间；场景中的猫与运行时观察、离开和回访逻辑统一读取 `story.cat`，不从预留数据推断剧情已启用。三维场景不绘制预留标记，调试地图用实心金色小点表示已启用落点、空心点表示未启用预留。猫群随所属世界释放，重开恢复初始姿态；第二层不启用 CAT01。

- 猫房：在可达通行格中寻找距猫群中心 3–8 米的观察点，以站立视高与视锥检查至少六个落点可见；墙体、书架和柜台按高度遮挡。当前九个落点使用小型、无交互碰撞的程序化猫占位，正式资产需按体积重新验收。
- 左右建议：按具体入口建立朝前方向，选择前方左右各一扇真实连接门；两门均需无遮挡、距离不超过 12 米且相对前方偏角小于 60 度。入场方向不适配就跳过，不能仅凭房间度数判定。
- 运行时：玩家进入对应房间并连续看见至少六只猫 0.8 秒才登记观察；正常穿门离开后猫倒下，回访重新观察才播回访字幕。死亡／传送原因不会伪装成正常离开。普通死亡已接入同层返回与状态保留，可从调试地图模拟；第二层可选凝视雕像接触可触发普通死亡。
- 左右门：从已匹配入口进入、靠近观察点、面向前方且看见左门时显示建议；字幕完整显示 4 秒才记为已传达。之后实际穿过对应右门才评论，提前离开、选左门或传送均不触发右门评论。
- 生命周期：同一时间只有一条字幕；触发时消耗、离开上下文取消、暂停冻结、新局重置。当前每种台词只触发一次，未加入等待、快走等扩展变体，也未接入语音。

这是猫场景与选路反应的首轮灰盒，不是完整 17 事件／两层梦境的验收。未接入偏好采集，所以首次猫台词只使用“看，它们也在看你。”，不声称玩家最喜欢猫。


## 18. 书架贴墙与灰盒表面

书架只在房间实际边界处生成，背板朝实体墙，背面与墙内表面间隔 2.5 厘米，以避让踢脚线；不在门洞保护格生成。书架长度沿墙布置，碰撞体随位置一同更新。交错布局中的中央障碍改用柜台，继续保留绕行动线；原隔断布局改为留白，不再生成独立高隔断。

墙体碰撞仍使用既有包围盒，显示几何取这些盒子的外边界：剔除墙段之间被遮住的面和共面的重复面，踢脚线顶面也只保留一层。书架背板、侧板、层板和书本按实际厚度装配；柜台主体在顶板下方结束，避免同一表面重复覆盖造成深度闪烁。


## 19. 凝视雕像空间适配与首轮威胁

第二层在已生成、已验证的地图中寻找安全示范与连续逃生条件；第一层不安排。候选位于现有出口路线，排除卧室、出口与猫房；候选到出口至少包含三间房。入口内侧观察点必须可达，雕像复位点距离观察点 6–10 米、视线无遮挡、可沿实际碰撞通路接近；观察点到出口具有不穿卧室的合法路径。匹配失败就不安排，不重抽地图迁就雕像，不改轮廓、门或家具。计划版本为 16。

首次进入遭遇房并看见雕像，或到达无遮挡的安全观察点附近后进入安全示范：雕像看得见玩家且失去手电照明时最多挪动 1 米，距玩家不足 3 米不再接近；挪动至少 0.3 米后，被实际手电照见并停住 0.6 秒，显示“你看着，它就懂规矩。”。4 秒演出窗口在遭遇房内推进，离开房间、双方视线被挡住或暂停不推进；未完成窗口始终无伤害，且至少保持 3 米距离才转为正式追踪。当前旁白使用无声字幕，窗口独立于字幕是否仍显示。

光照判断读取渲染手电的世界位置、方向、角度和射程，使用光锥内侧 80% 角度作为有效照停区，并同时检查玩家视锥与实体遮挡。照住则停止位移，但仍持续转向可见的玩家；未被照住且雕像能直接看见玩家时，才以 1.75 米／秒沿通行图追踪，碰撞半径沿用玩家半径。雕像视线从头部 1.54 米处检查到玩家站立视点 1.65 米处，独立于玩家镜头方向和手电；低矮家具不自动算作遮蔽。墙体或高家具阻断视线后立即停步，清空路径和目标，不再隔墙跟踪或转向玩家；再次露面恢复追踪，已完成的示范不重播。实际移动再次检查墙与家具碰撞，不能穿墙或在换房时删除。0.48 米内且无遮挡的接触触发死亡；示范、起身宽限、暂停与转场期间不伤害。

卧室是复位安全区；进入出口房结束该次追踪，雕像停在当前位置而不凭空消失，所有原有路线仍可选。普通死亡将雕像放回原复位点，保留示范进度、已完成状态与台词消费；重开清空。雕像能看见玩家且处于危险或示范期间时，抑制路线建议和行为评论；被遮挡后不持续占用该调度。调试地图用红色方块标出复位点、红圈标出观察点，并显示阶段。当前为程序化占位模型与凝视行为灰盒，未实现撞门声、关门延缓、隐藏结束等 B13–B16 剧情链，尚需自然路径试玩调整速度与提示。

## 20. 房间预设与道具组合

房间主题与轮廓、内装布局分开。`room.interior.presetId` 指向稳定的主题预设；预设定义每类空间障碍可以调用的 `prefabId` 组合；具体障碍继续由 `minX/maxX/minZ/maxZ` 提供占地与碰撞。相同 seed 可复现预设和组合，单独替换预制体外观不改地图拓扑。

首批预设为旧卧室、空客厅、旧育儿室、诊疗室、旧档案室和供奉室，分别组合床头柜／衣柜、沙发／展示柜、玩具箱／玩具架、诊疗床／药柜、写字桌／档案架、供桌／圣物柜。当前 `src/art/room-prefabs.js` 用程序化几何呈现这些稳定 ID，属于可运行灰盒；以后可将单个 ID 替换为 GLB，而不修改主题选择和布局逻辑。

可在 `generatePlan(seed, { roomPresetOverrides })` 中指定复现主题，例如 `{ default: 'clinic', 'room-2': 'archive' }` 会让普通房间默认使用诊疗室，并单独把 `room-2` 指定为档案室；出生卧室保持固定。未指定的房间仍由内装子种子选择预设。

预制体渲染必须落在计划障碍的包围盒内；碰撞、通行、故事槽位仍读取同一份纯数据计划。一个房间拥有独立 `presetId` 和一组障碍，每类候选按房间内序号轮换，减少整个房间只抽到重复道具的情况。新增主题时只扩展 `ROOM_PRESETS` 的数据组合和对应 `prefabId` 表现，不另造地图生成分支。
