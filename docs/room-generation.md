# 随机房间与内容编排

版本：v0.1；日期：2026-10-30。依据 [GDD](game-design-v0.2.md) 第 7–11 节。本文定义完整生成目标与失败处理。当前仅接入固定八房关系下的单层种子布局、11 种九宫格轮廓模板、四类内部布局、通行校验和保底；内容选择、任意拓扑、配对视听、跨层依赖与动态空间尚未实现。

## 1. 生成目标与计数

先确定本局要发生的内容及其关系，再安排房间、门窗、观察点和实体。单局以 4–6 个主要剧本为节奏目标；一条剧本可能跨多个房间，57 项内容不是 57 个房间。

计数使用 narrativeUnitId：B13–B16 合并为一个追逐单元；B26 与主流程共用卧室单元，不重复计算；B27／B28 是相应前置剧本的跨层尾声。技术布局可以增加连接房和安静路段，但不得用房间数量冒充实际体验时长。

确定性输入为 seed、已确认的偏好解释、contentVersion、rulesVersion、已确认内容计划。保存 planHash 与完整规划结果。AI 的重复调用不保证同结果，所以已经确认的计划不得在重进或死亡时重新请求；布局、装饰、声音变体使用独立随机子流，增加一个摆件不应改变地图拓扑。

## 2. 数据契约

| 数据 | 核心字段 |
|---|---|
| ContentPlan | planId、inputRevision、selectedUnits、dependencyEdges、exclusions、layerAssignments |
| RoomTemplate | templateId、轮廓／房型标签、允许尺寸范围、门槽、窗槽、入口落点、观察点、通行区域、内容落点、遮挡区域、承重与碰撞壳体 |
| Slot | slotId、roomId、局部变换、用途标签、允许包围盒、观察方向、占用互斥组 |
| SpatialRequirements | 节奏顺序、剧本实例关系、主路／分支、回访环、配对视听、追逐链、跨层前置与预留槽要求 |
| RoomLayout | templateBindings、房间变换与尺寸、配对门槽、几何边界、预留通道及空间检测结果 |
| RoomGraph | rooms、edges、start、exit、graphVersion、chasePaths、returnLoops |
| ScriptPlacement | instanceId、definitionId、roomBindings、objectBindings、observationVolumes、audioLinks |
| LayerPlan | graph、placements、reservedEchoSlots、assetBindings、validationReport |

门槽包含墙面、宽高、内外安全落点及是否双向；不以数组顺序代表方向。槽位允许范围与可通行范围分别定义，桌上摆件不能占用走道落点。窗、观察窗、镜面和监控是不同用途，不能仅按“有一个矩形面”互换。

模板可以随机改变允许范围内的尺寸与装饰，但关键构图、镜面角度、逃生宽度和群体视线属于硬约束。资产到位后按实际包围盒复验，不能只根据文件名假定不会挡门。

## 3. 生成流水线

管线归属 [技术框架的 planning 模块](technical-architecture.md#随机地图管线在架构中的位置)。输入是已确认偏好、种子、内容／规则版本和可用资源能力；输出是通过校验的纯数据计划及报告。以下阶段为目标接口，不代表已经存在对应代码。

| 阶段 | 输入 | 处理 | 输出与阶段检查 |
|---|---|---|---|
| 1 解释与确认 | 喜欢／害怕输入、玩家修正 | 语义服务或本地映射形成素材解释，玩家确认；区分真实生成与预设模式 | 固定的偏好解释及 inputRevision；不支持的输入提供兼容预设，不静默误解 |
| 2 选择内容 | 确认解释、可用剧本及表现能力 | 选择本局 4–6 个主要叙事单元，检查素材适配 | ContentPlan 初稿；按 narrativeUnitId 计数，不按建筑房间数计数 |
| 3 依赖与节奏 | 候选单元、互斥、前置规则 | 展开前置闭包，分配两层、强弱顺序、喘息、主流程和一次假醒 | 固定 ContentPlan；前置占用一并计入内容与节奏预算，不在此后偷偷塞入更多强烈事件 |
| 4 空间关系 | ContentPlan、剧本空间需求 | 建立主路、分叉、回访环、配对视听、连续追逐和跨层预留关系 | SpatialRequirements 与房间连接图初稿；此时不摆模型，不假定图上连通就等于实际可走 |
| 5 房型与布局 | 关系需求、房型库、布局子种子 | 为关系选兼容壳体，确定允许范围内尺寸、位置与朝向，配对门槽并预留通道 | RoomLayout、RoomGraph；检查重叠、门位、安全落点、通行与观察区域 |
| 6 内容落位 | 布局、槽位、剧本定义、资产能力 | 放置对象、家具、怪物、灯光与声源；绑定观察焦点、事件、旁白及状态实例 | ScriptPlacement 与 LayerPlan 候选；角色、物件和台词以稳定 ID 关联 |
| 7 校验与重试 | 完整候选、碰撞和状态变化规则 | 先校验硬约束，再计算软评分；失败按确定性尝试序列重建候选 | ValidationReport；未通过不得进入提交阶段，超限走第 8 节保底规则 |
| 8 提交与实例化 | 通过校验的计划、当前会话与转场标识 | flow 确认会话仍有效，由 state 一次写入图、位置、实例和版本 | 已提交梦层；新局、假醒和死亡使用不同初始化策略 |
| 9 表现加载 | 已提交计划、资源绑定 | presentation 构建 Three.js 场景；assets 加载或替换兼容占位资源 | 可呈现的场景；加载不重新抽图，进场前确认必需碰撞和内容表现就绪 |

生成器不直接创建 Three.js 对象。失败报告至少携带阶段、错误码、关联 roomId／instanceId、attemptIndex 和是否使用保底。流程只接受成功计划或明确失败，不读取候选中间状态作为正在游玩的世界。

### 房型选择与空间嵌入

房型沿用 GDD 确定的六组基础形状及用途：方形／长方形承载主要场面，L 形控制转角显露，凹室容纳局部内容，多出口支持分支与回路，狭长空间提供连接与过渡，大开放空间支持群体和远距离目击。形状与尺度参考 R.E.P.O. 的方向，具体尺寸与比例待灰盒调试；多出口是可叠加标签。

1. 对每个剧本读取所需出入口、观察距离、遮挡、通行、配对视听与对象容纳条件。
2. 筛选具备这些能力的模板，再按布局子种子选取允许的变体。模板旋转或调整尺寸后，门、观察点、落点和碰撞一起变换。
3. 配对实际门槽，放置房间；检查几何重叠、连接位置和玩家半径通行。邻接关系不能凭空跨过无门的墙面。
4. 先保护通道和观察区域，再分配装饰与内容槽。猫群、供台和大型模型不得挤掉已成立的回访或逃生条件。
5. 与关系图一起复验。轮廓漂亮但无法承载对应剧本时，换兼容模板或进入受限重试，不删掉剧本硬约束迁就外形。

首次实现采用 3 米网格单元组合房型、正交门槽连接和固定关系骨架，种子选择房型变体、朝向与间距。这是第一版布局实现，后续空间求解与拓扑扩展仍需遵守上述生成顺序与验收条件。

### 从剧本需求到实际路线的例子

以 CAT01 为例，先确定“初见 → 正常离开 → 探索其他空间 → 自然回访同一对象 → 继续前往出口”的关系，再选择能形成短回路的房型和门位。可用猫房两个入口，也可用相邻支路回程。门位、轮廓和家具可以变化，猫房实例及前后观察关系不能变化；玩家没看见初始场面时仍能离开并通关。

路线建议需要真实的左右合法分支、可见门和建议触发区域；它与猫房回路若共用空间，必须同时满足两套关系。具体分叉、汇合及行为判定见第 5 节，不能为了随机拼接切断主节奏或跨层前置。

### 资源与生成的时序

开局优先用已验证的资源能力和占位包围盒确定空间。模型任务完成后，按实际尺寸、朝向、材质与动画能力复验，再绑定到原 placement。模型生成时间不决定房间编号、门连接或已发生的剧情。

表现加载失败使用同一 placement 的兼容占位资源；最终模型不符合槽位时保留占位，不把它强塞进通道。若必需表现和占位都不可用，在玩家进场前返回失败或选择通过相同校验的保底计划。开始探索后不能因某个模型加载失败而重新随机整层。

## 4. 各类空间关系

| 组合 | 硬约束与验收 |
|---|---|
| C01 独立房 | 入口可见关键构图或可自然走到观察点，出口不被表现占用 |
| C02 回访房 | 有可执行的正常路线先经过初始状态、离开、再经过同一对象；不是仅数学上可以掉头 |
| C03 配对房 | 观察窗／门缝／声音连接真实成立，相关房间状态一致；窗后房不能在玩家进入时无故重新初始化 |
| C04 连续房组 | 威胁与玩家共享合法路径；跨门不删除威胁；临时关门和隐藏均有声明规则 |
| C05 跨层呼应 | 存在前置内容和预留槽，切层时检查真实观察事实后启用 |

猫房回访放在自然探索短环：卧室 → 猫房初见 → 分支空间 → 猫房另一入口／回程 → 向出口推进。不可用文字任务命令回头，也不能要求玩家完成观察才解锁出口；没看见可以错过表达，不能堵住通关。

## 5. 路线建议与偏离

在安全探索区布置左右均可见的分叉，两条路线均可通行并汇合到后续主路线。具体场面由兼容内容分配，分叉不把核心前置关系切断。首次实现采用两条短支路汇合，确保右路不因“不服从”受到额外惩罚。

RouteSuggestion 绑定 forkId、leftDoorId、rightDoorId、suggestionId 与出口区域。只有建议完成有效呈现后选择右路才生成偏离事实；未听见建议、直接绕过或先右转后播放建议都不成立。左右是建议发生时的门方位，转身后不重新解释。进入支路只记录一次选择，往返刷门不能刷评论。

两条路线不要求完全相同，但危险规则不得因偏离建议临时改变。两条分支各自验证可达出口、必需回访与跨层前置，不依赖旁白引路才能通关。

## 6. 两层计划与实际经历

开局生成第一层及第二层的空间骨架，预留呼应槽；语义与剧本选择结果固定。第一层结束时冻结可跨层事实快照，再实例化第二层条件内容。

| 内容 | 必须存在的事实 | 未发生时处理 |
|---|---|---|
| IN04 | 玩家确实观察源痕迹，并符合所选传播阶段 | 保留正常空间，不出现无依据痕迹或相关台词 |
| B27 | 玩家观察 B03 枯黑结果 | 使用正常床边装饰，不出现“恢复”事件或评论 |
| B28 | 玩家观察 B04 破损结果 | 床边不出现该玩偶，不评论“放近一点” |

选择前置剧本不等于玩家看见它。条件结果未启用时不临时抽另一个强烈事件，也不强迫补看。第二层启用决定记录在计划实例中；第二层死亡不重新计算前置或重新抽取。

## 7. 追逐布局与动态空间

B13–B16 使用完整模板链：侧门预警区 → 可关门延缓的过渡房 → 两条连通路径的杂物间 → 带遮挡点的侧室及怪物经过走廊。安全示范、怪物冲出位置和玩家反应距离必须成立。侧室隐藏点不是画面看不见就算隐藏，需通过怪物视线与路径检测；暴露后可以重新追逐。

临时门延缓属于追逐状态，死亡后复位；永久剧情变化保留。怪物不能出生在玩家落点内，也不能因关门直接永久失去路径。宽限时间、速度、开门延缓与安全距离通过配置集中调试，记录目标设备试玩结果。

B17 改门连接、B20 移除门走图事务；B19 倾斜与 BO03 呼吸先验证表现包络不侵入通道。每个动态变化必须验证发生前后和合法变化组合，不只验证初始布局。失败时保留原图，取消依赖该变化结果的台词。

## 8. 校验、重试与保底

硬约束：ID 唯一、引用存在、门槽不冲突、门两侧落点安全、角色半径可通过、起点到出口可达、必需关系成立、关键焦点可观察、追逐路径有效、前置与互斥正确、资产能力满足、动态变化后仍合法。

可达性包含拓扑与实际碰撞两层：图上连通不等于家具之间可走。对占位及最终资源包围盒检查通行栅格／导航区域；对状态变化按允许状态组合验证。验证器输出错误码和关联 roomId／instanceId，不只返回 false。

软约束：重复主题间隔、强弱节奏、视听焦点冲突、路线长度、昂贵效果数量。软评分不能抵消硬失败。十分钟是试玩目标，路径长度与预估演出时长仅用于筛选，不作为达标证据。

首次实现给每个输入最多 20 次确定性尝试，attemptIndex 派生子种子并写入报告。这是可调初始值，不是已验证的性能上限。重试保留确认后的 ContentPlan，只重选兼容模板、布局和落点，不重新调用语义服务或悄悄替换玩家已确认的内容。超限优先选择兼容当前 ContentPlan 的已验证保底布局；若只能使用同偏好类别的保底内容计划，必须在进场前明确告知使用保底方案，生成新的计划标识并完整校验。保底保留核心流程、回访、路线选择和一种威胁。保底布局亦须通过相同校验，不允许跳过校验强行开局；如资源损坏导致保底也无效，显示可重试错误，不把玩家放入不可通关地图。

## 9. 测试与诊断

固定种子测试覆盖两层、猫／花语义、全套关系与互斥；每个剧本至少在一个合法布局演示。批量生成用代表性种子集和边界输入，记录失败率、原因、重试次数和保底使用；通过一组种子不意味着任意输入都已证明合法。

必须额外检查：死亡不重抽、装饰子流不改变拓扑、同版本同输入复现、改变内容版本能识别不兼容、未见前置无跨层结果、左右分支均通关、追逐不因卸载中断、门变化失败可回滚。

调试视图显示房间图、门槽、观察体积、回访环、追逐路径、事实依赖、资产占用及失效原因。支持导出 planHash、完整纯数据计划与事件日志供本地复现；导出不包含密钥。真人试玩分别验证方向感、自然回访、恐怖节奏和无旁白通关。


## 12. 房间内部布局与装饰

房间生成分为四层：外轮廓 → 门口位置 → 内部布局 → 装饰细节。相同外轮廓与门位允许绑定不同内部布局，书架、隔断、柜台等结构参与动线和视线组织；颜色、书本排列等只作为外观变化。布局随机子流与外壳、装饰分开，替换装饰不得改变碰撞或通行关系。

| 布局 | 空间作用 | 当前灰盒表现 |
|---|---|---|
| 中央绕行 | 中部实体迫使玩家选择两侧路线 | 偏离中心锚点的低柜台组合 |
| 隔断分区 | 分隔前后区域，保留绕行缺口 | 高隔断组合 |
| 交错书架 | 交替遮挡视线，产生曲折路线 | 两侧交错的书架与书本 |
| 沿墙陈设 | 物件靠外围，保留较开阔的中央区域 | 外围书架组合 |

当前模板根据可用网格、旋转和门位裁剪；布局名称表示生成意图，不保证每个小房间都有完整组合。无法保持内部连通的家具候选会被跳过。没有足够可用位置时允许减少家具，不以堵路换取密度。

当前实现保护房间中心、出生点、门口内外网格、床和猫房内容落点。每件新增家具保守占用一个网格，剩余网格必须在房间内部连通；随后基于墙体及家具碰撞体建立通行图，验证所有门口、房间中心、出口、双分支及回访所需连接。渲染、移动碰撞和调试地图读取同一份障碍数据，不在加载场景时再次随机摆放。

布局种子支持生成器参数 interiorSeed，默认继承地图 seed，用于固定外壳时单独验证内装变化；菜单仍只提供统一地图种子。同一种子在同一生成版本下可复现，生成规则升级后不承诺复现旧版地图。

后续剧本适配需要声明观察视锥、遮挡高度、逃跑通道宽度、追逐绕行和演出空间；当前只实现基础可达性与内容落点保护，尚未实现自动视线构图验收或完整追逐约束。柜台、书架和隔断仍是程序化灰盒资产，密度、尺度与绕行节奏需真人试玩调整。


## 13. 九宫格轮廓规则

房间以一个大正方形为边界，划分成 3×3 空间模块，选取连通的模块组成轮廓。模块不是独立房间，相邻占用模块之间默认连通，不自动生成内墙或门；内部隔断由后续内装层决定。多出口是连接属性，不单列为轮廓。

当前模板如下，1 表示房间空间，0 表示未占用区域；允许整体旋转：

| 轮廓 | 由上到下三行 |
|---|---|
| 完整方形 | 111 / 111 / 111 |
| 长方形 | 111 / 111 / 000 |
| 十字形 | 010 / 111 / 010 |
| L 形 | 100 / 100 / 111 |
| T 形 | 111 / 010 / 010 |
| U 形 | 101 / 101 / 111 |
| 回字形 | 111 / 101 / 111 |
| 缺角方形 | 110 / 111 / 111 |
| 双角缺口 | 010 / 111 / 111 |
| 工字形 | 111 / 010 / 111 |
| 直条形 | 010 / 010 / 010 |

## 14. 固定出生卧室

出生卧室不参与随机外壳、内装与装饰抽取，沿用当前 seed 42 的 T 形、旋转 180 度、中央绕行内装样式。轮廓、门口、窗面、床、柜台、墙面色调、灯光与出生位置／朝向保持一致，成为每局稳定的起点。固定入口朝向，门外连接距离与后续房间继续由种子决定；保底地图也使用相同卧室。

本规则仅约束开局生成，不取消剧本明确要求的卧室状态变化或假醒演出。普通死亡和重开仍遵循各自的状态保留规则。
