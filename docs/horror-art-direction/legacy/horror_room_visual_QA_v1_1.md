# 《心里有鬼》Codex 房间生成审美检查清单 / QA v1.1

> 目的：房间预设、道具组合、灯光调整、事件显现前后都必须做的**可验证审美自检**。
> 与同目录 `codex_horror_room_research_v1_1.md` 配套使用；6 张用户图片在 `references/user-images/`。
> 本文件是**设计验收协议**，不是对真实源码结构的断言。所有文件路径、控制接口和渲染参数需在项目中核实。

## 0. 质量门槛与检查次序

**顺序不可倒置**：P0 技术阻断 → 正常房间识别 → 视觉构图 → 情绪异常 → 两次观察 → 叙事节奏 → 来源/原创性 → 性能与可访问性 → 截图归档。

- `P0 / BLOCKER`：破坏通行、碰撞、房间连通、事件触发、种子可复现、严重帧率异常、非法覆盖资产等。**任何一项失败必须先修复，不允许用审美评分抵消。**
- `P1 / MAJOR`：房间用途不可识别、光照无法阅读、所有异常堆在入口中心、视觉规则失效、与相邻房间同质化。
- `P2 / POLISH`：轻微道具密度、单件配色、边缘阴影、局部磨损或布料形状问题。
- `UNKNOWN`：项目工具无法读到或未手动验证的项，明确保留，**不得伪造 PASS**。

## 1. 生成前的 30 秒策划自检

- [ ] 我能用一句话描述：**房间原本是用来做什么的**？
- [ ] 我能用一句话描述：**玩家应该怀疑的是什么**？不是泛泛的“很诡异”。
- [ ] 本次主语法只有 1 个，辅助语法不超过 2 个；不同时堆叠全部恐怖效果。
- [ ] 本房的恐怖强度符合它在地图中的角色（连接/主事件/短场面/喘息），未擅自变更房间角色。
- [ ] 选了 U01–U06 中**至多 1 个**视觉显现母题，或明确标记“无”；不把 U02 怪物造型当作随机装饰。
- [ ] 已确认现有房型、入口方向、出口方向、重要交互点，以及真实玩家视高和 FOV 的获取方式。
- [ ] 已说明参考图片的用途：仅研究构图，不复制具体人形、布景、图案或摄影作品。

## 2. 构图：第一眼、第二眼、第三眼

### A. 第一眼 — 空间可信度

- [ ] 进门自然视线中，房间类型能够辨认（卧室、走廊、诊疗室……）。
- [ ] 出口/可行走区域在视觉上仍可理解；不是一团黑。
- [ ] 家具至少形成 2 个**有生活逻辑的物件簇**，不是独立随机点阵。
- [ ] 有清晰的视觉主轴、消失点或主焦点；非故意情况下不出现多个互抢注意力的高亮物。
- [ ] 前景遮挡/中景用途/远景疑点有层次；若没有远景，用一个空白区代替也需有意图。

### B. 第二眼 — 不舒服但说不清

- [ ] 异常来自**关系**（位置、朝向、重复、遮挡、比例、灯色），而不只是“放一个恐怖物件”。
- [ ] 至少能指出一个具体的不匹配：例如“所有椅子朝门，只有一把朝墙”。
- [ ] 若以过度对称制造不安，是否存在一个小且有意义的破绽，而不是机械镜像复制？
- [ ] 若以空白/阴影制造不安，玩家从合理位置有机会看到其边界或二次信息？
- [ ] 若用病态颜色，颜色有物理/叙事来源；未依赖整屏滤镜？
- [ ] 若没有人形，静止空间本身仍具有轻微不安感？

### C. 第三眼 — 可被玩家亲自确认

- [ ] 已定义 `entry`、`notice`、`recheck` 三个自然观察位置；不依赖自由飞行导演摄像机。
- [ ] 玩家可通过走近、侧移、回头或抬头，观察到新信息或可信遮挡变化。
- [ ] 不要求精确卡像素、极端俯仰或破坏游戏正常操作才能看到设计重点。
- [ ] 视线变化产生的是“发现”，不是远处 asset popping、深度排序错误或灯光闪烁故障。
- [ ] 允许玩家错过该恐怖细节时，不会误伤必过的剧情触发与交互逻辑。

## 4. 房间物件组合的失败征兆（任意出现即回退重做候选）

- [ ] **“乱就是恐怖”**：物件随机堆叠，无法解释生活用途或谁摆在这里。
- [ ] **“红就是恐怖”**：只换成满屏红光，没有位置关系、光源理由或层次。
- [ ] **“暗就是恐怖”**：截图看不清门、地面、交互物与空间边界。
- [ ] **“怪就是恐怖”**：普通连接房必刷恐怖人形，毫无强弱节奏。
- [ ] **“穿模就是梦境”**：故障被包装成超现实，且没有明确设计逻辑。
- [ ] **“对称就是美”**：每个房间都镜像摆满家具，形成酒店样板间观感。
- [ ] **“复制就是参考”**：重建可辨认的电影场景、恐怖角色、独特道具与墙纸。
- [ ] **“截图好看就够了”**：只有一张任意摄影机截图，玩家实际位置看不到重点。
- [ ] **“每间都最恐怖”**：缺少普通房与喘息房，玩家逐渐对异常麻木。

> 上述是**反例勾选项**。出现问题时勾选并标记 FAIL；全部不勾不代表自动 PASS，还要完成下面的技术验证。

## 5. 逐房 P0 技术与流程回归（必须真实执行）

- [ ] 同一房型、同一 `seed` 重入两次，构图/选择状态应符合既有确定性规则。
- [ ] 出入口与路径全程可达；主线交互物、可视提示与必要触发区未被遮挡。
- [ ] 道具碰撞与墙/门/天花板没有不合理交错，接缝没有严重光漏。
- [ ] 家具布局尊重房间实际尺寸；人物和道具的缩放具备一致的尺度参照。
- [ ] 未意外增加敌人状态机、刷怪器、碰撞体或视觉后处理的全局副作用。
- [ ] 事件房显示/隐藏规则仍与已有场面配置一致；未改变地图分叉、环路等既有约束。
- [ ] 改动前后的运行性能无明显回退；移动设备/现场演示设备目标需依据实际测试明确。
- [ ] 明暗可读；避免持续闪烁、强烈强制摇屏、诱发不适的高频条纹。
- [ ] 变更文件可追踪且能回滚；保留原版预设与素材，未未经许可覆盖。

## 6. 每房 6 项审美评分（0–5）

| 维度 | 0–1 分 | 3 分 | 5 分 |
|---|---|---|---|
| **正常生活可信度** | 看不出用途 | 功能明确但道具生硬 | 可信的生活秩序，异常有参照 |
| **视角构图** | 无主焦点/随意摆 | 有焦点但二次观察弱 | 入口、遮挡、深度、二次发现相互配合 |
| **心理不安感** | 只靠黑、红、怪物 | 有单点不适 | 即使关掉怪物也能产生“哪里不对” |
| **物件叙事关联** | 物件互不相关 | 部分道具有共同暗示 | 道具关系令玩家自然推测过去发生过什么 |
| **房间间节奏差异** | 处处相同强度 | 有变化但不稳定 | 连接、事件、喘息有明确心理落差 |
| **游玩可读与原创** | 迷路/照搬/阻挡 | 可玩且有一定区分 | 易探索、原创，借鉴机制而非直接复制 |

**建议通过线**：无 P0，六项平均 ≥4.0，且任何单项不得低于 3。只是**内部建议阈值**，不是比赛评分规则；项目负责人可根据实际试玩调整。`UNKNOWN` 不可当成 5 分。审美评分不等于玩家真的被吓到：如果可行，应让非开发者试玩并记录第一次注意到什么。

## 7. 确保比较公平的截图规范

对同一候选房间，至少截取：

1. `entry` — 玩家正常进门，看见哪个方向、哪个主物体。
2. `notice` — 玩家第一次可能注意到异常的位置。
3. `recheck` — 玩家靠近/侧移/抬头后重新确认的位置。
4. `baseline` — 修改前**同种子、同机位**截图（若项目可复现）。

如果测试 U03 光色，额外录制 `A 基线 / B 暖黄或灰绿 / C 局部红光`，保证**几何、视点、物件**不变；不允许把多因素混合改动当作同一个 A/B 结论。

建议命名（只是产物建议，不要求现有系统已经支持）：

```text
art-reviews/{seed}/{room_id}/
  baseline-entry.png
  candidate-entry.png
  candidate-notice.png
  candidate-recheck.png
  candidate-light-A.png
  candidate-light-B.png
  room-review.md
```

截图必须来自**实际游戏渲染**，不能用概念图宣称已落地。尚未实现或无法截图时写 `NOT IMPLEMENTED`，不要伪造路径或状态。

## 9. 给 Codex 的最简执行指令

> 阅读本检查单与 v1.1 总规范。针对本次改动的每个房间，先说清“正常用途、恐怖疑问、参考母题、观察路径、光源道具”。然后基于真实玩家相机截 `entry / notice / recheck`。对同一随机种子进行两次回归，检查门、碰撞、事件和性能。按本文件 P0/P1/P2 分类并填写六维审美评分。**未通过或未验证就不得宣称完成**。除非收到明确授权，不修改既有地图拓扑、怪物事件逻辑或批量覆盖美术资产。

**终极自检问题**：去掉所有怪物、血迹、尖叫与镜头特效，这个房间是否仍让人感觉“熟悉，但有哪里绝对不对”？
