# 统一执行顺序与交付门槛

日期：2026-10-31。86 张卡各有一个首次开工批次；能力卡、现有流程卡会跨批回归和补验，不按编号顺序从零做完。当前任务只完成规格审查与排期，所有运行完成度以实际证据为准。

## 执行方法

- **一个程序集成任务推进一批小改动**，chen 可制作已交接的独立资源；双方不同时改 world.js、main.js 等共享入口。
- 首批先让三个自带场面进入正常地图；随后才扩大内容池和完整预算。P01/P02/P05 的最小部分先用起来，不能等 S01–S09 全部结束才做第一间房。
- 本表是优先级与首次介入顺序，不是整批全通过才启动下一批的串行瀑布。没有依赖的资源与独立预览可以准备；进入正常随机池必须满足相应卡的能力、语义和表现条件。
- 内容分布沿 [编排方案](../content-scheduling.md)：整局 4–6 主要单元＋4–6 短场面；每层真正喘息；覆盖与空白间隔是调试目标，硬约束优先。声音缺失、待定分支或空壳实例不能为凑数入池。
- P 卡是 S02 等能力的具体交付，非新剧情。依赖中的 S01/S03/S04 指所需的实例／字幕／表现切片；S05 指本卡实际必要声音，不是必须先录完全游戏旁白。S02 动态图事务、S04 专用形变均延后到对应场面。

1. 场面不是空注册项：初见、忽略、合法触发及最终状态可读；声音关键场面须有实际声音。

4. 不破坏现有两层流程、固定卧室、凝视规则、猫房或 chen 的资源；运行代码测试与构建通过，视觉在浏览器复核。

6. 先检查并保存当前未提交工作的归属；提交和推送仍须用户授权，不为排期自动整理他人的改动。
