## 实际接入方式

1. `src/planning/client.js` 的正式请求默认 `themedRooms:true`。`generateDream` 在原地图、剧情、威胁、主动玩法全部落位后调用 `populateThemedRooms`；旧独立调用默认不开启，便于既有场景及对照回归。
2. [运行布局表](../../src/art/themed-room-recipes.js) 注册医院、游乐场、公司、个人住宅、旅馆、祭祀各八套。独立确定性排序使用种子和房间ID，不消耗原地图随机数序列。
3. 整套功能布景按米制旋转、平移到真实房间里的完整可用区域。保留原房型、门洞及天花，不复制预览门板、四面墙或窗口。5×10和10×10布局必须找到足够空间；不压缩家具。
4. 用实际占地替换区域内旧普通家具，旧桌椅组整组替换；区域外不相撞的辅助陈设保留，防止大房间只剩一个小物件组。新家具占地进入 `plan.obstacles`，按正式导航与事件校验事务式接受；失败完整回退。
5. 固定出生/开场、出口、追逐、威胁、动态房间、已保留的故事空间不改。其他静态事件保留所有既有专用物件、观察点及原本通畅的视线关系。
6. `dark-interiors.js` 分流到 [正式渲染适配器](../../src/art/themed-room-runtime.js)，只读取已保存布局，不在加载时随机摆放。共用缓存、限制并行加载、关闭时释放资源；模型失败保留原占地灰盒并报告。
7. 已接入灯光同事的逐间配置；正式模式关闭每房半球环境光叠加，仅启用玩家当前所在房间的专用灯组。原游戏手电、VHS及事件信号触发不改。

## 查询与开关

- `plan.themedRooms`：池版本、48候选数量、实际 `placed` 与 `skipped` 原因。
- `room.interior.themedRoom`：布局ID、平移/旋转、替换与新增碰撞ID。
- 世界根节点 `userData.themedRooms`：实际加载数量、失败和支撑跳过；核验页以可读报告展示。
- 对照时显式调用 `planDream(seed,{themedRooms:false,...})`，或直接比较 `generateDream(seed,{...options,themedRooms:true/false})`。无需删除资产或修改地图种子。
- 新旧地图的房型、门位与事件布局保持；完整 planHash 因新增布景元数据和碰撞而改变。不能宣称新旧完整计划哈希相同。
