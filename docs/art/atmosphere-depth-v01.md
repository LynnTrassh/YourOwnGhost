# 暗室纵深与旧家具表面响应 V1

## 本轮落地

主游戏现有 `dark-interiors` 已使用本轮修改的灯光与模型加载模块，无需新增 world 接口。独立对照页同样调用 `createWorld`，使用种子 1844070019 第二层。预览地址：`/art-source/atmosphere-depth-v01/index.html`。

- 维持最多 3 盏室内投影灯、2 盏局部补光的既有预算。选灯时优先保留当前房间的顶灯，其余灯兼顾空间分布，减少近处台灯集中占用名额。
- 顶灯光锥下限从 1.2 调到 1.28 弧度，既有强度乘 1.08；桌面实用灯乘 .88，减轻孤立亮斑。
- 顶灯增加弱局部反射近似，参与原来的两盏补光预算；窗边补光扩大范围并稍偏冷。全局环境亮度仍为 .52，手电、曝光、颗粒、边缘偏色保持原值。
- 原始 v03 木家具的常量粗糙度从 .9 小幅调至 .78，书桌 .8。只处理明确列出的木质家具且没有粗糙度/金属度贴图的材质。新 PBR 模型不套用此校正。单张图集含小配件，因此这不是逐部件材质重做。
- 新增的补光无阴影，是便宜的间接光近似，不是真实 GI；局部隔断处仍需人工观察漏光。

## 与另一对话布局对齐

已读取“设计三间恐怖房间构图”的进度，以及 [48间制作方案](themed-room-production-v2.md)、`src/art/themed-room-designs.js`。该方案仍在推进，正式随机池尚未接入。其独立展示器使用自己的舞台灯，本轮通用灯光修改不能被称为“48间逐房布光已完成”。

后续逐房调光以 `hero / composition / reveal / ceiling / lighting` 的既定发现顺序为准：

| 布局 | 应呈现的层次 | 应保留的暗部 |
| --- | --- | --- |
| hospital-02 末班候诊室 | 两排椅子和中央通道分两段照明，前景足以辨认用途 | 最后一格灯关闭，反向孤椅留给手电发现 |
| hospital-04 检查室 | 窄工作光落在床旁空地，床尾路线可读 | 不自动把灯重新瞄准检查床，否则会消除设计异常 |
| hospital-07 病案封存库 | 整理台形成焦点，侧柜获得低亮轮廓，巷道有前后层次 | 高柜背后和末端空墙保持低亮，不均匀填平 |
| park-02 无人领奖台 | 暖白舞台、低亮观众席、奖杯细高光 | 帷幕后方保持暗，反向观众椅靠回望发现 |
| park-03 室内游艺厅 | 低饱和蓝绿屏幕，兑换台微暖，机器错列形成遮挡 | 远端背向机器不独立打正面亮光 |

当前主游戏通用模块只根据房间与灯具位置分配预算，不读取这些文字字段，不擅自解释剧情焦点。布局方接入正式房间时需提供有意关闭的灯、灯具朝向和发现区域；不能只增加亮度或让所有灯同时亮。独立舞台与规划文件仍由原对话维护。

## 检查与证据

- JS 语法检查、`npm run build` 通过；构建仍有现有的大分块提示。
- 浏览器在实际世界预览中对卧室、档案室、诊所完成同机位 A/D 对照；[记录](../../art-source/atmosphere-depth-v01/captures/observations.json) 中六次计划哈希均为 `30628351`，计划和碰撞快照未改变，模型加载失败数为 0。
- 观察到的提升主要是侧墙、柜边和近地面的暗部层次；仍保留深处暗区。档案室另外检查了手电关闭，台面和侧墙仍能辨认。
- 观察范围内室内投影灯不超过 3、局部补光不超过 2；浏览器日志无 error/warn。没有进行 GPU 性能计时或真人试玩，不能据此承诺帧率提升。
- 诊所现有白色事件占位模型仍在；该问题不属于灯光修复。新版48间逐房视觉验收也未包含在本轮结果中。
