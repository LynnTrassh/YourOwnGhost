# 双人协作约定

双方使用各自的仓库副本，共同维护 `main`。AI 行为规则见根目录 [AGENTS.md](../AGENTS.md)。不用功能分支，不代表可以同时修改同一批文件；并行工作依靠责任分工，公共入口由一方集中接入。

## 日常流程

1. **开工同步**：检查本地改动和远端状态，确认任务范围。玩法／程序方负责逻辑与公共接入，chen 负责美术资源、独立表现模块和美术交接文档。
2. **各做各的**：每个任务使用独立任务卡，不同时改同一张总表。不同资产可并行，同一模型或共享代码文件不能由两边同时编辑。
3. **交接接口**：chen 提供资源路径、预览、尺度、原点、朝向、包围盒、材质与使用说明；程序方负责加载、碰撞、状态和性能整合。需要改共享入口时，先完成独立资源或模块，再交接接入。
4. **小批集成**：完成一个可验收的小功能或一批资源后检查、中文提交；用户授权推送后同步到远端。另一方拉取后检查自己的内容是否仍能运行。
5. **共享文件轮流修改**：确实需要 chen 修改公共入口时，由双方明确交接具体路径。接收方从交接提交开始，原责任方暂停这些路径，完成后再交还。

任务声明只有到达远端、被另一方同步后才可见，不能当成实时锁。两边同时推送时，Git 通常会拒绝后推送者的旧历史；被拒绝的一方应同步并整合，不得强推。即使 Git 自动合并成功，尺寸、接口、资源引用仍可能冲突，需要相关测试和游戏内检查。

## 给双方 AI 的开工提示

> 先读根目录 AGENTS.md 和 docs/collaboration.md。本次我代表【玩法／程序方或 chen 美术方】，任务是【目标】。按默认文件分工执行，先检查本地与远端状态，只修改本任务范围。不要覆盖其他任务的改动，不自行建分支；需要共享文件时先明确交接。完成后报告验证结果，提交和推送按我的明确授权执行。

`AGENTS.md` 需要两边拉取到本地才能生效；如果使用的 AI 工具不自动读取它，在该工具的项目指令中加入“每次工作前读取并遵守根目录 AGENTS.md”。不要维护多份独立规则副本。

## 任务卡模板

路径：`docs/tasks/YYYYMMDD-owner-topic.md`。owner 使用稳定的身份名称，例如 `gameplay` 或 `chen`。这是普通任务记录，不是自动执行的锁或权限系统。

```markdown
# 任务名称

- 责任方：
- 状态：进行中 / 待接入 / 待验证 / 已完成
- 起始提交：
- 目标：
- 修改范围：列出文件或独占目录
- 依赖与交接：需要另一方提供或接入的内容
- 验收条件：
- 验证结果：明确已验证和未验证项
- 交付提交：未提交时填写“未提交”
```

任务卡由本任务责任方维护。新增的跨方任务不自动表示对方已接受。不要自动发消息或替对方承诺排期。

## 首轮合作边界

固定出生卧室作为第一批美术样板。chen 可在 `docs/art/` 记录视觉方案，在 `art-source/` 保留源文件，在 `public/art/` 导出可用资源；程序方将资源接入现有固定卧室。

卧室布局和玩家出生视角当前固定。改变床、门口、隔断的位置属于空间设计调整，不作为纯换皮默默实施。资产达到“已导出”、程序达到“已接入”和双方达到“已验收”分别记录。
