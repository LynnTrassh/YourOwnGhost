# UI 与跨设备操作设计 v0.1

日期：2026-10-31。状态：视觉方向已确认，独立 UI／输入模块已实现；主游戏接入与手机真机验收待完成。适用工程：YourOwnGhost。

延续 [游戏设计](game-design-v0.2.md) 的探索、观察、开门与逃生循环。本稿提议在桌面体验之外增加手机浏览器支持，不改变剧情、移动上限或通关条件。以下数值均为首轮调试起点。

## 1 当前问题与方向

已检查 `index.html`、`src/style.css`、`src/main.js`、`package.json`：

- 开始页同时摆放偏好填写、种子、调试地图、画面设置和操作说明；暂停沿用同一面板，信息层级不清。
- 移动依赖 WASD，交互依赖 E，手电依赖 F；现有拖动视角仍使用鼠标移动事件，不能当作完整触屏控制。
- 目前只有鼠标灵敏度、VHS 强度和镜头微动设置；没有双摇杆，也没有操作模式选择。
- 当前版本暂无音效，字幕承担旁白；刷新会重置进度。不能在新 UI 中做出已有声音或持久存档的承诺。
- Vite 只监听本机 127.0.0.1，手机不能直接通过电脑的这个地址访问。

推荐方向：**安静的梦境入口、克制的局内界面、独立设置、键鼠与触屏共用动作层。** 手机先支持横屏；双摇杆为默认方案，右侧滑动环顾作为可选方案。

## 2 视觉语言

保留当前灰绿、旧纸白与暗卧室气质。背景采用已有卧室静态视角或低频微动，按钮和文字保持清晰，不跟随 VHS 扭曲。恐怖发生在房间里，菜单不使用随机闪烁、假报错或突然移动的按钮。

| 元素 | 建议 |
|---|---|
| 背景 | 深墨绿 #0B1210，覆盖层约 90% 不透明；避免文字直接落在复杂场景上 |
| 主文字／次文字 | 旧纸白 #E8E5D8／灰绿 #B5C0B5；关键说明不用极低对比度灰字 |
| 强调色 | 暖灰金 #C6B48B，用于选中态、焦点与主按钮；危险操作用暗朱红搭配明确文字 |
| 字体 | 中文标题宋体，正文系统黑体；不依赖远程字体加载 |
| 尺寸 | 桌面标题 56–72 px、手机 32–40 px；正文 16 px，辅助文字至少 14 px |
| 控件 | 手机点击区域至少 48×48 CSS px，间隔至少 8 px；摇杆底盘直径约 112 px |
| 动效 | 淡入淡出 150–250 ms；减少动态效果时关闭背景微动与菜单位移 |

所有页面提供可见的键盘焦点，选中态同时用边框或标记表达。设计颜色仍需在实际背景上检查对比度。

## 3 开局流程

### 3.1 标题页

桌面：左侧标题与三个入口，右侧保留卧室空间。手机竖屏：单列；横屏：左右分栏并允许内容滚动。

```text
心里有鬼                      [卧室、半开的门]
YOUR OWN GHOST
门外的房间，似乎又换了位置。

[ 进入梦境 ]
[ 设置     ]
[ 操作说明 ]

包含恐怖与动物死亡表现。
当前试玩版暂无音效，旁白以字幕呈现。
```

正常标题页不显示种子、覆盖率、技术状态和调试地图。没有跨刷新存档时不显示“继续游戏”；当前页面内暂停后可显示“继续探索”。浏览器网页不承诺自动关闭窗口，退出使用“返回标题”。

### 3.2 入梦前：两步自由描述（用户确认后的修订）

第一步“你喜欢什么？”与第二步“你害怕什么？”均使用大文本框，可描述任意事物、场景、感觉、外形、声音或动作，不限制为预设类别，不自动压缩成单一标签。每栏最多 1200 字符是提交负载约束，无语义白名单。

例如喜欢“雨天的旧书店，还有会发光的水母”，害怕“没有脸的人，站在远处，一直模仿我的动作”。完整保留原文，返回编辑保留草稿。生成内容后续由语义／资产／玩法层适配，不用现有猫花等预设冒充生成结果。参考图片是视觉提案中的可选未来能力，本轮不展示无效上传入口。

第三步“梦正在成形”并列展示两段原文与修改入口，使用真实阶段理解描述／生成梦境／准备进入，不虚构进度或预计时长。生成服务未接入、失败或取消时明确说明并保留原文。

已与技术方案对齐：当出生卧室与无主题开场区域 ready 时可先入梦，后续区域后台生成；此时文案为“开场已就绪”，不是“所有生成已完成”。玩家开始后后台任务所有权交给玩法，UI 销毁不能取消已移交作业。正式生成方案与 PCG 边界由对应任务接入。

### 3.3 操作确认与加载

确认页底部：`操作方式：触屏双摇杆 ▾`，可在开始前改为键鼠。触屏竖屏可完成填写，进入游戏前提示“请横过手机”；提供返回设置入口，不困住用户。

点击“开始入梦”后进入加载态，禁止重复点击。没有可信总量时用“正在准备房间…”而非假百分比；失败提供重试与返回。桌面由用户点击触发鼠标锁定，触屏直接进入且不依赖 Pointer Lock。未来音频接入时同样在主动开始动作中启用。

第一轮床上教学按动作逐条出现：环顾 → 起身 → 移动；完成即淡出。起身前按现有剧情规则限制移动，不因为摇杆出现就绕过剧情。

## 4 局内 HUD

桌面仅保留中心小点、有效目标提示、字幕、右上暂停入口。移除常驻英文品牌、房间名和整行键位；不增加小地图、梦层编号、任务箭头、血条或怪物状态，以免剧透与破坏空间判断。

- 对准并靠近门：`[E] 开门`；起身时：`[E] 起身`。无有效目标时不显示动作提示。
- 手电只显示真实开关状态，不虚构电量。短按 F 或触屏按钮切换。
- 字幕默认开启，建议最多两行；长句按语义分页且保留合理阅读时间。手机字幕放在双摇杆上方，避免拇指遮挡。
- 操作说明可随时从暂停页打开。提示消失不等于玩家无法重新学习。

手机横屏示意：

```text
┌──────────────────────────────────────────────────────────┐
│                                              [Ⅱ 暂停]    │
│                                                          │
│                            ·                             │
│                         门：可打开                        │
│                                                          │
│                  字幕在这里，不压住控制区                  │
│                                      [开门] [手电]       │
│     ◎ 移动                                ◎ 环顾         │
└──────────────────────────────────────────────────────────┘
```

交互按钮位置固定，无目标时保留低透明度底座并禁用，有目标时显示“开门／起身”等具体动作。右侧按钮在摇杆上方，避免与摇杆触区重叠。允许松开环顾后点击交互，同时左手继续移动；三指同时移动、环顾、交互也必须有效。手电与交互按钮不得触发相机拖动。

## 5 操作方式与双摇杆规则

设置提供 `自动 / 键盘鼠标 / 触屏`。自动模式综合触点能力、粗指针和实际输入判断，不只依据屏幕宽度或设备名称；进入游戏前显示实际选中的模式。手动选择优先并记住。自动模式只在标题／暂停状态更新布局，不能因一次误触在追逐中突然换 HUD。

| 动作 | 键鼠 | 触屏 |
|---|---|---|
| 移动 | WASD | 左摇杆，按相机水平方向前后左右移动 |
| 环顾 | 鼠标，支持锁定失败后的拖动备选 | 默认右摇杆；可改为右侧滑动区域 |
| 当前交互 | E | 固定位置的情境按钮 |
| 手电 | F | 独立手电按钮 |
| 暂停 | Esc 或页面按钮 | 右上暂停按钮 |

左摇杆默认固定底座，便于第一次找到；可选浮动底座，触点必须开始于左下控制区。建议半径 48 px、死区 15%，死区外重新映射为 0–1 速度，斜向归一化，最大速度与键鼠一致。先不新增跑步、跳跃、蹲伏等玩法。

右摇杆代表转动速度：偏移越大转得越快，持续按住可以持续转身；松手立即停止。水平满量程初值 150°/秒，垂直初值 100°/秒，可调范围随后通过实机测试收敛。保留当前俯仰限制，不允许镜头翻转；默认关闭加速度。向右推动向右看，向上推动向上看。

可选“右侧滑动环顾”代表滑动距离，适合习惯手机第一人称操作的玩家；两种环顾方案互斥，不同时生效。默认仍交付用户提出的左右双摇杆。

模式切换只在暂停／设置发生，流程为：冻结世界 → 释放鼠标锁定和触点 → 清空按键与摇杆向量 → 更新控件及提示 → 用户点继续 → 恢复。切换保留当前位置、世界变化和本局输入，不重开地图。触屏模式下的鼠标锁定变化不能误触发恢复或再次暂停。

## 6 暂停与设置

暂停页主项依次为：继续探索、设置、操作说明、重新开始、返回标题。暂停冻结移动、威胁、剧情计时与字幕推进，未来音频也同步暂停。进入子设置仍保持暂停，返回暂停页不自动恢复。

重新开始提示“从第一层重新开始，本局进度将丢失”，可选择保留当前偏好；返回标题涉及丢弃当前局时也需确认。正常调整设置与切换操作方式无需反复确认。

| 分类 | 第一版提供 | 规则 |
|---|---|---|
| 操作 | 自动／键鼠／触屏、鼠标灵敏度、触屏环顾灵敏度、双摇杆／滑动、固定／浮动左摇杆 | 键鼠与触屏灵敏度独立保存；无关选项随模式收起 |
| 画面 | 流畅／标准／精细、VHS 强度、镜头微动 | 手机默认流畅；画质与输入模式分别设置 |
| 字幕与舒适度 | 字幕大小、背景透明度、减少动态效果 | 当前无音频版字幕保持开启，避免丢失旁白；未来配音完备再允许关闭 |
| 声音 | 当前显示“此版本暂无音效” | 音频接入后才显示主音量／环境音／旁白音量，避免无效滑块 |

每个分类有“恢复本页默认”，不提供误清空游戏进度的混合按钮。设置即时预览并本地保存；存储不可用时本次会话仍可使用并轻提示。保存设置不等于保存游戏，明确“刷新会重新开始”。偏好原文不因 UI 改造新增上传或长期保存。

结尾保留“你醒了”，提供“再做一个梦”和“返回标题”。重玩种子放进开发工具，不作为正式结尾主选项。

## 7 手机布局、性能与浏览器边界

Three.js 并不限定桌面。当前 WebGLRenderer 依赖 WebGL 2，应在启动前做能力检测；不支持时给出可读说明与返回入口。能够渲染和能流畅通关是两项验收。

- 菜单支持竖屏与横屏，游戏首版横屏。旋转到竖屏自动暂停、清空输入；转回后点击继续，防止重新出现画面时已被追上。
- 使用动态视口尺寸与安全区内边距，避开刘海、底部手势条和浏览器工具栏；不依赖强制全屏或强制锁定方向才能玩。
- 触屏游戏区域禁止浏览器默认拖动手势；菜单仍正常滚动和填写，不能全局禁止所有触摸行为。
- 每根手指按 pointerId 分配到固定控制区并捕获；移动后跨区不抢占另一摇杆。pointerup、pointercancel、lostpointercapture、失焦、后台、暂停都清零相关输入。
- 输入框聚焦时不响应游戏按键；软键盘收起后重新测量视口，按钮不能留在屏幕外。
- 流畅档先以 DPR 上限 1、降低手电阴影分辨率、降低或关闭 VHS 后处理为起点；标准档可从 DPR 1.5 起。不要照搬当前上限 2 到所有手机。
- 不能通过关闭玩法需要的视线判断、威胁或场面来提帧。画质降低后仍需辨认门、危险征兆和手电照明反馈。
- 初步性能目标为选定手机持续游玩约 10 分钟接近或高于 30 FPS，记录帧时间、发热和降频；桌面争取 60 FPS。以上是目标，尚无实测结论。
- 浏览器模拟触屏只能验收布局与事件；iOS Safari、Android Chrome 必须真机验证。内嵌浏览器先不承诺支持，失败时提供“请在系统浏览器打开”。

开发时需显式将 Vite 绑定局域网地址或 0.0.0.0，手机与电脑接入同一网络，通过电脑局域网 IP 的 4190 端口访问；这是本地测试条件，不是部署完成。本次设计不修改监听配置或发布网站。

## 8 实现拆分与验收

建议分三批，每批保持桌面可玩：

1. **界面分层**：标题、偏好向导、暂停、设置、结尾独立；调试页仅开发模式进入。保留现有解释偏好与生成地图逻辑，不重写玩法。
2. **统一输入与手机闭环**：键鼠／双摇杆统一产生移动、视角、交互和手电动作；加入模式切换、安全区、旋转暂停和多指处理。
3. **真机调优**：画质分档、触屏灵敏度、字幕与拇指遮挡检查；用正常路线完成两层流程。

程序接入建议：新增 `src/input/` 管设备输入，新增 `src/ui/` 管界面状态；`src/main.js` 负责连接既有剧情和世界。移动、脚步声源、镜头摆动都消费统一移动结果，不能留下只识别 WASD 的分支。交互通过现有玩法权限检查，UI 不直接开门或跳过起身条件。

UI 状态建议：标题 → 偏好 → 准备 → 游玩 ⇄ 暂停／设置 → 结尾。剧情转场期间锁定输入，转场完成后按游戏状态恢复；死亡／假醒不重新显示开局向导、不重置操作偏好。

| 验收情景 | 必须通过 |
|---|---|
| 桌面全流程 | 开始、偏好确认、锁鼠标、起身、移动、开门、手电、暂停、两层结尾均正常 |
| 手机全流程 | 无物理键盘完成上述所有必要动作；走正常路线，不靠调试传送 |
| 多指 | 同时移动与环顾；交互／手电第三触点不使两个摇杆跳动；松开任一手指不影响另一根 |
| 模式切换 | 两个方向都可切换；不漂移、不自动开门、不改变本局地图与剧情 |
| 暂停与后台 | 追逐时暂停、锁屏、切应用后世界不继续推进；恢复无残留输入 |
| 方向与尺寸 | 竖横切换、工具栏伸缩、软键盘弹出收起后控件仍可见；小横屏菜单可滚动 |
| 剧情状态 | 起身前、死亡、假醒、结尾触控符合相同权限；无一次点击连续穿透两个动作 |
| 偏好与破坏操作 | 任意原文交给生成接口；失败不改成预设；返回不丢草稿；重新开始及弃局有确认 |
| 可读性 | 字幕、按钮不被手指、刘海遮挡；VHS 不影响菜单阅读；减少动态效果生效 |
| 兼容与性能 | 至少一台 iPhone Safari、一台 Android Chrome 记录型号、系统、浏览器、连续游玩和帧时间 |

## 9 依据与交付边界

- [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer)：当前渲染器使用 WebGL 2。
- [Three.js WebGL 能力检测](https://threejs.org/manual/pages/webgl-compatibility-check.html)：不支持设备需要提前检测。
- [Three.js 响应式渲染](https://threejs.org/manual/pages/responsive.html)：画布显示尺寸与渲染分辨率需要分别处理，不能无条件拉满高 DPI。
- [MDN 多点触控](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Multi-touch_interaction)、[pointercancel](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event)：独立追踪触点并处理浏览器取消输入。

独立模块与接入契约见 [UI 接入说明](ui-integration.md)。正式玩法和生成服务仍由对应任务接入，没有创建存档系统或证明手机已能完整通关。默认双摇杆、颜色、尺寸和灵敏度为首版方案，需要真机手感验证后收敛。
