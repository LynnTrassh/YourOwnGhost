# 心里有鬼 Your Own Ghost 游戏设计文档 v0.2

本作是一款以玩家喜欢与害怕的事物为素材的单人第一人称 3D 梦境恐怖游戏。玩家从鬼压床中挣脱，在熟悉却不断失常的房间中寻找出口；以为醒来之后，才发现自己仍在梦里。

本版明确游戏的核心体验、系统规则、开发阶段与验收标准。工程已开始实现基础探索原型；下述内容为完整设计目标，具体完成情况见 [开发记录](development-log.md)。本文为当前设计入口；[剧本总集](script-catalog.md) 收录逐项演出和台词，[制作与技术规则](production-rules.md) 收录制作约束。

技术实现设计见 [技术框架](technical-architecture.md)、[剧本与旁白运行规范](script-narrative-runtime.md) 和 [随机房间与内容编排](room-generation.md)。这些文档中的初始参数用于开发调试，不代表已通过体验验收。

## 1 版本与工程范围

- 编写日期：2026 年 10 月 30 日；版本：v0.2，完整设计基线。
- 工程目录：`YourOwnGhost`。

## 2 核心体验与玩家目标

一句话卖点：梦知道你喜欢什么，也知道怎样让它变得可怕。

玩家的明确目标是找到出口并真正醒来。主要行动是观察、移动、开门、回访与逃生；不以战斗、收集道具或解谜作为通关主循环。

体验递进为：熟悉与安心 → 数量或行为异常 → 喜爱物被破坏 → 威胁逼近 → 看似脱险 → 假醒后的不信任 → 真正醒来。恐怖场面可以独立成立，不必为每个异常补充凶手、解释或追逐。

四项设计支柱：

1. **个人相关性**：偏好决定可发生的事件，而不仅是怪物皮肤。猫可以凝视和死亡，花可以过量和枯萎，音乐可以重复和骤停。
2. **梦的连续性**：房间记住玩家已经见过的变化。普通死亡不洗掉世界，剧情假醒才改变梦层。
3. **可理解的恐惧**：画面一次突出一个事件；实际危险有征兆、有可学习规则、有逃生路径。
4. **被观察与反驳**：梦会对玩家真实行动作出回应。玩家可以不听建议、回头确认或修正梦的理解，后续表达应承认这些差异。

本项目从《史丹利的寓言》取用“叙述与玩家行动之间的张力”作为设计方向：声音可以建议，玩家可以不照做，梦必须回应实际发生的选择；不照搬角色、台词、完整剧情或结局。从 R.E.P.O. 取用空间探索和可学习威胁的方向，不因此加入联机、回收经济或物理搬运主循环。

## 3 平台与操作提案

使用 Three.js 开发，初期以桌面浏览器、键鼠、单人体验为目标。优先保证目标设备上能稳定完成全流程。

| 输入 | 功能 |
|---|---|
| WASD | 移动 |
| 鼠标 | 环顾 |
| E | 起身、开门等当前可用交互 |
| F | 手电开关 |
| Esc | 暂停与设置 |

开始页说明包含恐怖场面及动物死亡表现，并提供开始和退出选项。主动开始后启用声音及鼠标控制；失去焦点时暂停。交互提示仅在靠近有效目标时出现。设置提供主音量、旁白音量、字幕显示和鼠标灵敏度；调试入口不占正常游玩画面。

## 4 单局流程与节奏

完整体验目标约 10 分钟，首次试玩后校准，不用等待或重复走廊填满时长。开场和收束合计约 1 分钟，第一层约 4 分钟，第二层约 5 分钟。

| 阶段 | 玩家经历 | 设计目的 |
|---|---|---|
| 输入与入梦 | 填写喜欢和害怕的事物，确认游戏理解；从床上起身 | 建立个人关联和基本操作 |
| 第一层 | 看见喜爱物过量，探索短回路，再次经过时发现毁坏 | 建立观察与回访的因果 |
| 第一层出口 | 跨过看似安全的出口，回到相同卧室 | 唯一一次主要剧情假醒 |
| 第二层 | 门外路线改变；已经历的细节回到视野；面对一次可学习的威胁 | 动摇安全感并推动逃生 |
| 第二层出口 | 到达出口，真正醒来，显示结束与重新开始 | 给出明确完成反馈 |

每局完整目标为 4–6 个主要剧本，搭配安静房间与有限追逐；剧本数量不等于建筑房间数量。首版制作先完成第 9 节的最小闭环，再扩充到目标节奏。最小闭环是制作阶段，不代表完整内容范围。核心流程条件在生成结果上校验；具体场面随空间机会与玩家实际行为发生，可选支路和未触发场面允许错过。

## 5 首个代表剧本 猫房

素材：玩家喜欢猫。主题：喜爱物过量、群体注视、喜爱物毁坏。组合：自然回访。

初次进入时，大量猫同时注视玩家；玩家离开并经由短回路自然回来时，猫全部倒地、闭眼、静止，原本的猫叫消失。数量以画面能形成群体压迫感且性能稳定为准，可从 24 只开始调试。

| 状态 | 进入条件 | 呈现与持久规则 |
|---|---|---|
| 尚未观察 | 首次进入或尚未看清群体 | 猫存活并凝视；单纯进门不消耗事件 |
| 已观察 | 群体位于视野内、未被遮挡，并达到可调的连续观察时间 | 记录玩家已看见初始场面 |
| 已离开 | 已观察后通过正常出口离开 | 提交猫死亡状态，保存在梦层数据中 |
| 回访 | 再次进入或从另一入口重新看见 | 全部死亡，静默；后续重进和普通死亡都不恢复 |

地图必须提供自然回程，不用任务文字要求玩家检查猫。这个房间不伤害玩家，不加隐藏凶手、线索搜集或附加追杀。死亡传送不算正常离开；若玩家未完成观察，死亡不得提前消费事件。猫死亡状态在第二层不自动复用；本剧本实例不跨层继承。

猫房旁白先承认玩家看到的事实，再轻描淡写地回应：初见“这不是你最喜欢的吗？……看，它们也在看你。”；回访“啊呀呀……怎么都倒下了。”。离开与停留分支见 [CAT01 完整剧本](script-catalog.md#3-cat01-满屋的猫)。语气亲昵、假惋惜，不揭示凶手，也不让玩家听完才可离开。

## 6 威胁与失败

首版建议只制作一种可学习威胁：凝视雕像。玩家用手电实际照见它时，它停止；离开光照或视线后，它靠近。首次遭遇用安全距离和短距离移动展示规则，再引入危险。接触判定导致死亡，不引入复杂血量或战斗系统。

逃生段应跨至少两个相连空间，怪物按同一追逐状态持续行动；过门不能让威胁凭空消失。路线保持可通行，追逐终点明确结束危险。死亡后从本层卧室起身，威胁回到指定复位点，并给予足够起身和重新行动的宽限。

听声者调查最后的脚步声位置，玩家可停止发声并避开该位置；避光者被照见后退、熄灯后靠近。三类行为分别制作完整遭遇与反制规则，每局优先突出一种，分阶段接入，不要求首个版本同时出现。外观与行为分离，换模型不等于新增行为能力。

三种威胁均有安全示范旁白，台词与触发见 [剧本总集第 6 节](script-catalog.md#6-可供情节调用的威胁行为)。凝视雕像示范句结束后才进入正式危险段；玩家始终可以行动。行为示范旁白与 B13 起段台词共享首次遭遇窗口，同次相遇只选一句，死亡后不重播。

完整连续追逐按 B13 侧门冲出 → B14 关门后退 → B15 杂物间绕行 → B16 侧室躲避制作。关门只能短暂延缓，撞门声提示阻挡即将结束；杂物间有两条连通绕行路；侧室遮挡使怪物失去视线并经过，关键脚步远离后才结束危险，暴露则重新追逐。失败后复位怪物、临时门与追逐阶段，保留永久变化及语音消费记录，并给予起身宽限。

## 7 梦层与状态规则

| 事件 | 保留 | 重置或改变 |
|---|---|---|
| 普通死亡 | 当前梦层、地图、已提交永久变化、真实行为事实、旁白消费记录 | 玩家位置、临时受伤与追逐状态、明确允许复位的物件 |
| 剧情假醒 | 声明需要跨层读取的经历 | 切换到第二层地图，按新剧本初始化房间；全局一次性台词不重播 |
| 离开并重进房间 | 房间剧本阶段和最终状态 | 可重建画面对象，不能重抽剧情 |
| 重新开始 | 不保留本局状态 | 创建新局与新种子 |

刷新页面暂按重新开局处理，暂停菜单明确提示。跨刷新存档不纳入首版必做项。

房间生成先安排剧本关系，再安排连通空间与合法点位。回访房要有回程，配对房要有可用视听联系，追逐房组要有连续出口。同一种子应复现同一布局及剧本分配；普通死亡不重新随机。

观察使用视野、遮挡与连续可见时长，初始调试值为 0.8 秒。进入、看见、正常离开、回访、死亡传送与剧情假醒是不同事件；不得用“进过房间”代替“看见场面”。暂停冻结观察、运动和演出计时。

跨层读取仅限 IN04、B27、B28 以及主流程声明的事实，其他房间实例不自动继承。若没有真实前置经历，不生成对应呼应。

允许空间变化，但门、碰撞、通行与状态必须一起更新。无意义的永久走廊拉长、每开门回卧室和堵死必经出口不作为玩法。

## 8 个性化与内容编排

目标链路：喜欢与害怕的输入 → 语义理解 → 兼容剧本与行为选择 → 空间及节奏校验 → 外观描述 → 资产生成或载入。

AI 负责理解素材并在受限剧本中选择，确定性规则负责保证出口、状态和节奏合法。不执行模型返回的代码；不存在的剧本、未知行为和非法引用必须被拒绝或回退。

首版先用有限输入和明确映射验证两种不同语义，例如“猫 → 凝视与死亡”“花 → 过量与枯萎”。玩家可修正解释；不支持的输入明确说明并提供可选预设。若尚未接入模型服务，界面和演示均标明预设映射，不宣称实时 AI 生成。

真实语义服务与 Tripo 外观生成属于完整个性化目标，安排在基础闭环完成后接入。等待或失败时提供可玩的占位方案，不无限阻塞开始游戏。静态模型替换不等于完成动画、绑定或行为。

个性化资产的扩展链路、提示词组成、房间主题色、绑定与动画验收见 [个性化美术资产与动画流水线](personalized-asset-pipeline.md)。全局美术造型规则保持一致，模型颜色根据所在房间配置生成与布光；Tripo 生成、绑定和动作适配分别作为异步任务及验收阶段，不假定任意名词都可成功绑定。

每个剧本卡至少包含：实例 ID、主题、素材适配、空间关系、初始状态、观察条件、触发条件、最终状态、危险规则、死亡复位、跨层引用、旁白与互斥条件、资产需求及验收结果。不能只随机摆物件，再补写一个事件名称。

编排顺序为：用既定 11 种九宫格轮廓生成空间与门连接 → 识别实际结构机会 → 匹配兼容剧本并校验依赖与节奏 → 确定观察点、放置模型和声源 → 复验通行、视线及事件条件 → 提交完整梦层。不预排固定游览路线；没有发生的探索行为不能被剧情或旁白假定发生。CAT01 与 AB01 不竞争同一对象组，不默认连续出现；镜像、监控与因果错位不同时争夺同一关注区。避免连续两个群体注视或连续两次回访毁坏。强烈场面之间保留真正安静的路段。IN04、B27、B28 必须连同前置剧本一起选择，不能单独抽取结果；B27 依赖 B03 枯花目击，B28 依赖 B04 破损玩偶目击，两者不同时争夺床边关注。

资产生成初期按每局最多两项任务控制范围，模型加载前校验格式、体积、尺度和朝向。任务需有超时、失败终态及重试去重；网络超时不得直接重复创建任务。密钥留在服务端，前端使用项目任务标识；只发送所需物体描述。动画、骨骼、镜面和形变需独立制作。此处为接入要求，不代表服务已经可用。

### 房间形状与空间关系

房间形状与空间尺度以 R.E.P.O. 为参考方向。以下房型是本项目采用的基础房型库；具体比例、轮廓与空间尺度仍需结合场景观察和灰盒试玩确定，不代表对参考作品房型的逐项复刻。

空间关系决定哪些房间相连、哪里需要回访或分支；房间壳体决定轮廓、可开门位置、内部通行和视线遮挡。生成器先安排剧本所需的空间关系，再挑选符合条件的房型装配，两者共同满足事件需求。

| 基础房型 | 主要用途 | 装配重点 |
|---|---|---|
| 方形、长方形房间 | 卧室、猫房、宴席等主要场面 | 留出可读的主体构图、观察距离与通行区域 |
| L 形房间 | 转角后显露异常、局部声音引导 | 通过转角控制视线，保留明确可走的路径 |
| 带凹室的房间 | 供台、柜子、床及局部恐怖场面 | 凹室提供内容位置，不侵占必经通道 |
| 多出口房间 | 路线选择、自然回访、追逐绕行 | 出入口对应真实连接，分支与回路能够实际通行 |
| 狭长连接空间 | 接近威胁、声音引导、节奏过渡 | 保证通行与事件所需视线，不用无意义拉长填充时长 |
| 较大的开放房间 | 群体、巨大尺度与远距离目击 | 保证主体在目标距离可辨，控制同一时刻的关注点 |

“多出口”是可与轮廓组合的房型特征，例如 L 形房也可以有多个出口。房型不与剧本一一绑定，同一种轮廓可以服务多个剧本，同一剧本也可使用多个满足约束的房型。

每个房型同时定义可开门的墙段、通行区域、观察点、内容落点和遮挡区域。房型选择以剧本需求为依据：猫房使用两个出入口形成回路时，要保证入口和群体视线匹配；也可使用邻近支路回程形成自然回访，不把两个入口设为所有猫房的强制条件。追逐房保留绕行与逃生空间，配对房保证视听联系，路线建议处保留两条合法分支。

具体尺寸、门宽、转角尺度和摆放密度仍需灰盒调试。当前已实现固定空间关系下的单层种子房型布局与通行校验；完整剧本选择、两层条件编排和六组房型覆盖仍待实现。

## 9 开发优先级与阶段计划

先验证核心玩法与旁白回应的闭环，再完善个性化与内容多样性。各阶段以验收结果作为推进依据。下表是实施顺序，不是对完整范围的删减；全量内容以第 11 节及剧本总集为准。

| 优先级 | 范围 | 完成标准 |
|---|---|---|
| P0 必须完成 | 从开始页到两层梦境再到结局的完整流程 | 无调试跳转完成一次通关 |
| P0 必须完成 | 猫房初见、自然回访、死亡保留 | 看见前不消费，看见后按规则变化 |
| P0 必须完成 | 一种威胁、连续逃生及死亡返回 | 有征兆、可理解、有逃生空间 |
| P0 必须完成 | 有限个性化分支 | 至少猫与花两种兼容场面，不把预设称为 AI 生成 |
| P0 必须完成 | 声音、提示、暂停、重新开始 | 目标设备完整可操作，调试界面可隐藏 |
| P0 必须完成 | 主流程及猫房旁白、路线引导／偏离回应、行为事实记录 | 不同实际选择产生对应回应，不重播、不编造行为 |
| P1 系统扩展 | 真实语义选择、跨层呼应、受限种子变体、其他行为分支 | 每项有实际演示证据；不破坏 P0 |
| P2 后续扩展 | Tripo 个性化资产、房间主题色适配、可绑定模型、基础追逐动画、更多剧本、多怪物、镜面和复杂形变 | 逐项制作与验收，记录生成、加载、绑定和动画状态；失败时仍可玩 |

| 阶段 | 工作重点 | 完成标准 |
|---|---|---|
| 工程基础 | 明确技术方案、建立工程、确定首批剧本 | 能启动并进入可移动房间 |
| 流程灰盒 | 起身、移动、门、两层地图、出口、假醒、主流程旁白 | 可从头走到结局 |
| 核心场面 | 猫房、自然回路、世界状态、观察记录、场面旁白 | 核心场面可重复验收 |
| 玩法闭环 | 单一威胁、连续逃生、有限偏好分支、路线选择与回应 | 可完整体验观察、变化、选择反馈与逃生 |
| 个性化扩展 | 语义服务、跨层呼应、种子变体 | 不同输入产生适配且合法的体验 |
| 体验打磨 | 声画、节奏、完整试玩与问题修复 | 核心验收通过，记录实际体验时长 |
| 内容扩展 | 更多剧本、怪物、生成资产与特殊表现 | 每项独立验收后加入完整流程 |

核心流程稳定前，优先修复阻塞、状态与通行问题；新内容逐项接入，持续保留可从头到尾游玩的版本。

## 10 旁白、选择与行为记忆

### 旁白是梦中的一个角色

旁白知道玩家主动输入的喜好，并观察玩家在游戏中的反应。它亲昵、从容、装无辜，偶尔带一点忍住的笑，用轻描淡写的态度对待异常。它可以诱导、说反话、假装惋惜，但不解释自身身份，不承认制造了死亡，也不替场面补出凶手。

叙述可以在态度上不可靠，引用的事实必须可靠。它可以说“这点小事”，不能在玩家没有回头时说“你又回头了”。不能把一次停留解释成玩家的真实人格、病症或心理结论。

| 主流程触发 | 台词 | 限制 |
|---|---|---|
| 初次睁眼，环境可辨认 | “醒了？给你留着门呢。” | 初醒句结束后再接其他旁白 |
| 第一层出口已进入视野 | “你看，出口一直在那儿。” | 出口当前可见，不用台词冒充视线引导 |
| 假醒后看清相同卧室 | “啊，回来了。还是这儿睡得惯吧。” | 不解释梦层机制 |
| 真正醒来已明确发生 | “好吧。这次就送到这里。” | 不追加第二次假醒或惊吓 |
| 本局首次普通死亡后起身 | “慢一点。又没人催你。” | 起身宽限内播放，后续死亡不重复嘲讽 |

### 玩家怎样反驳旁白

选择主要通过移动、观察和离开表达，不强制弹出对话选项。旁白建议的路线可以不走；已定要求是两条分支均合法通行、回应匹配真实路线。两条分支的具体场面、汇合位置和观察顺序尚待细化。

不服从不自动导致惩罚或死亡；危险由对应剧本的可学习规则决定。建议不是通关指令，不把“听话”设置为唯一正确路线。不会为了展示分支而增加多个结局；两层梦境与真正醒来的主结构保持成立。

每个剧本有场面旁白；以下行为回应作为额外分支，全部制作，但只有事实成立且没有场面台词、危险或关键声音时才播放。每局最多播放两次此类评论，同一行为只回应一次，避免梦变成不停点评的导游。

| 行为事实 | 触发条件 | 台词 | 语气 |
|---|---|---|---|
| 没走建议路线 | 旁白实际介绍过可见的左门，玩家随后走右侧合法分支 | 引导：“左边也给你开着呢。”；右转后：“哦，右边。你自己挑的。” | 随口邀请后微微满意；两条分支均通行，不惩罚不服从 |
| 回头确认 | 看清场面后转开，再看回同一焦点 | “嗯，还在。放心了吗？” | 只在对象确实还在时播放，不对消失剧本误用 |
| 绕开威胁 | 玩家进入威胁观察区后，通过无追逐的旁路安全离开 | “这么客气，连招呼都不打。” | 假装替威胁遗憾 |
| 拒绝空座 | RI01 拉椅演出后玩家正常离开，未坐下 | “留着吧。它们不赶时间。” | 温柔、不挽留到阻塞出口 |
| 修正偏好解释 | 玩家实际提交一次修正并确认 | “好，按你说的来。我记着呢。” | 顺从中带暗示；不能虚构玩家曾修改 |

事实记录只决定是否播放，不允许旁白替玩家编造经历或判断人格。场面发生原因继续留白；旁白的装无辜与反话不改变系统实际记录。

路线建议、场面评论和行为评论分开记账。每局最多两次的上限仅针对上述五类额外行为评论，不限制主流程与场面旁白；同一行为本局只回应一次。RI01 的邀请属于场面旁白，“拒绝空座”属于行为评论。B26 与主流程卧室共用台词和消费记录，不重复计数。

建议的有效接收、视线转开与回看、同时满足多个行为时的选择顺序，仍需细化为程序判定参数。不得把尚未播放的建议视为玩家已经听过，不把普通鼠标抖动算作再次确认。

### 播放规则

每个剧本制作场面旁白；Meta 行为评论作为独立层，只在事实成立时加入。一般先让玩家看见或听见事实，再说台词；B02 的起奏前句、TI01 的坠落前句等按剧本明确的演出顺序执行，不能提前透露尚未发生的结果。关闭旁白后仍能理解场面与完成游戏。

- 全局同时最多一句。场面旁白优先于行为评论；主流程转场作废旧房间台词。危险征兆与逃生信息优先于评论，不用旁白遮住关键声音。
- 以“本局＋剧本实例＋阶段＋台词”记录消费。句子开始即消费；普通死亡、重进和暂停恢复不重新触发，新局才清空。跨层主流程句按本局记录。
- 死亡立即停播，剧情转场取消旧场景语音。暂停冻结播放位置和演出计时，恢复后继续，不能从句首重播。
- 玩家离开触发区、场面状态已改变或危险开始时，相关过期台词作废，不排队追播。明确的离开评论在正常过门时单独判定，要求空闲且无危险，不继承原房间排队句。
- 停留评论以主句结束后再停留 5 秒作为初始调试值；“很快离开”的具体时间窗口待定，不与停留门槛混为同一个已定参数。离开与停留分支只消费其中一个。不得锁镜头或锁门强迫听完。
- 字幕与语音同步；旁白音量和字幕可分别设置。声音播放失败时字幕可继续表达该句，不反复触发。旁白不产生怪物可以追踪的世界噪声。

### 事实记录与调度边界

世界状态保存梦层、剧本阶段与永久变化；行为记录保存事件类型、对象／实例、梦层、发生顺序及是否有效观察；旁白状态保存当前句、消费集合和互斥分支。画面重建不得清空这些数据。

回应先检查事实、阶段、空间和优先级，再选择台词。AI 可参与素材语义和受控表达，不能凭空添加行为事实或绕开播放规则。首批使用固定台词与确定条件验证调度。

## 11 全量内容与制作要求

完整内容为 **CAT01＋28 个扩展剧本＋28 项基础场面**，逐项制作与验收。它们不是 57 个独立房间：CAT01 是一个多阶段剧本，基础追逐片段可以组成一个连续房组，主流程、三类威胁行为与 Meta 回应不重复计数。每局仍只选择 4–6 个主要剧本。

## 12 视听与信息设计

空间以可辨识的日常室内为基础。卧室在假醒前后保留关键陈设，门外改变形成对比。照明保证出口和威胁线索可辨，不以全黑代替恐怖。

声音用于标记状态：活猫声与回访静默、威胁移动提示、真正安静的喘息段。一次只突出一个主要事件，追逐期间不插入长旁白。Meta 回应只能引用实际记录的行为，不给玩家编造经历或人格结论。

原型阶段可用简单几何和占位音画。后续外部资产单独记录来源、许可与加入时间；不能将下载或生成时间误写为素材全部由团队原创。

## 13 验收与试玩

| 检查 | 通过标准 |
|---|---|
| 全流程 | 从开始页起身，经过两层、一次剧情假醒并抵达结局，无调试帮助 |
| 观察门槛 | 未看清猫就离开再返回，初始场面仍可体验 |
| 自然回访 | 正常探索路线使玩家再次经过猫房，不依赖文字催促 |
| 状态持久 | 猫已死亡后再次进房或普通死亡返回，仍为死亡状态 |
| 死亡区分 | 死亡不换梦层或地图；第一层出口才触发剧情假醒 |
| 追逐连续 | 过门后威胁持续按规则工作；玩家可通过明确路线逃脱 |
| 个性化 | 猫与花输入产生不同且语义适配的场面；未知输入可回退 |
| 生成合法 | 所支持种子出口可达、必经门不被占用、回访关系成立 |
| 暂停与重新开始 | 暂停时事件不偷偷推进，重新开始不残留上一局状态 |
| 选择回应 | 分别走左侧建议路线和右侧合法分支；只在右转事实成立时播放偏离句，不惩罚不服从 |
| 评论预算 | 五类行为评论逐项验证；每局最多两次，同一行为一次，不挤占场面台词 |
| 行为真实性 | 未观察、未回头、未遭遇威胁时不播放对应行为评论 |
| 旁白调度 | 同时一句；追逐及关键声段不被覆盖；离房、死亡、转场后过期句不补播 |
| 消费与暂停 | 死亡重进不重复已开始句；暂停冻结、恢复续播；停留与离开分支互斥 |
| 跨层呼应 | 分别检查前置事实存在及不存在的两种路径；不出现无依据物件或台词 |
| 无旁白游玩 | 关闭语音和字幕后仍可辨认出口、场面变化并完成游戏 |
| 内容覆盖 | 总集每项均有状态；未制作或未验收项目不标记完成 |
| 完整体验 | 在目标机器实际通关并记录时长、明显卡顿及遗留问题 |

自动检查只证明状态与布局规则；恐怖表达、输入手感、音画和实际时长需要真人试玩。目标约 10 分钟未实测前不能写成已达成。

完整试玩路径：填写偏好 → 初见猫房 → 自然回访变化 → 第一层出口与假醒 → 第二层规则性威胁 → 真正醒来。可录制从正常入口完成的游玩过程用于复查；调试场面预览不替代完整流程验收。

## 14 待定事项

渲染使用 Three.js，开发与构建使用 Vite，采用 JavaScript ES Modules。后续需确定语义服务方案、资产生成流程、剧本卡的运行参数、语音资源映射，以及行为分支的判定参数。旁白声音、录制方式、音频资源预算和最终表演需单独确定。技术选型应优先满足个人开发的维护成本、稳定性和迭代效率。
