## 2. “什么都可以生成”的工程定义

**输入词汇开放、语义保留、表现路径可组合；执行能力仍由游戏提供和验证。** 不需要为每个新名词增加 if 分支，也不把“失败时有预设可玩”计为自由输入成功。

三种产物都属于生成结果：物件模型、环境配置、事件组合。具体物件原则上走其本体生成；抽象输入通过经玩家确认的可见／可听情境表达，不能无说明地换成摆件。多主题不静默裁掉，否定与修饰也不丢失。

开放输入不等于能够保证任意字符串都一次成功，也不代表第三方生成或复杂骨骼百分之百可靠。超出可执行能力时应保留原意、解释缺口、尝试兼容表达；无法兑现时明确失败，而不是把无关模型称为成功。安全拦截、无意义文本、供应商拒绝与技术失败分别报告。

| 输入例子 | 保留的意思 | 生成／适配路线 | 不可接受的偷换 |
|---|---|---|---|
| 喜欢红色电吉他 | 颜色、物件、乐器属性 | 生成吉他；重复陈列、供奉、消失；若强调声音，则必须接声音表现 | 改成花，或只有“吉他”文字 |
| 害怕蛇 | 蛇形、贴地运动 | 蛇模型＋蛇形绑定／路径身体适配；依能力进入潜伏、经过或威胁 | 把蛇缩放成人形包络，悬空滑行冒充爬动 |
| 喜欢音乐 | 听觉体验 | 音源编排＋对应发声装置；重复、错拍、骤停 | 只有静音音乐盒模型也算完成 |
| 害怕深海 | 水深、看不清、巨大未知 | 深水窗口／水下轮廓／环境声与尺度构图；玩家仍在安全通行面 | 默认理解成害怕鱼，直接送入鱼怪追逐 |
| 害怕被遗忘 | 自己存在痕迹消失 | 玩家确认后，照片缺席、空位、痕迹消退的情境组合 | 根据一句话诊断玩家，或要求改填人偶 |
| 喜欢猫但怕它们盯着我 | 喜爱主体与恐惧关系共存 | 同一语义主体绑定两个角色，保留 gaze 关系；必要时只问一次确认 | 将“猫”同时简单标成喜欢／不喜欢，丢掉条件 |
| 喜欢下雨但不喜欢雷声 | 雨为正向、雷声排除 | 窗外雨景、雨声；明确禁止追加雷声 | 只提取“雨／雷”，把否定当喜好 |
| 三条腿的玻璃鲸鱼 | 虚构形态与材质 | 生成外观，测量体型；静态／水下呈现或专用运动；关键外形不对就重试 | 因不在词典里拒绝，或自动改成普通鲸鱼 |

表中除既有条目外均是待实现适配方案，不能标成目前已经支持。

## 3. UI 重新设计

标题页保持上一版气质；点击进入梦境，出现两张可自由填写的卡片：

```text
你喜欢什么？
[可以是一个东西、一种声音，或者一种感觉……]

你害怕什么？
[也可以写清楚：你害怕它的哪一点……]

[让梦理解]                     [返回]
```

不显示“仅支持猫和花”，示例只是提示，不是限定。按 UI 任务交接，每栏最多 1200 字符，分别保留喜欢／恐惧原文；这是负载约束而非主题白名单，前后端需统一计数方式，不截断后默默生成。手机可竖屏填写，软键盘期间按钮可滚动到达，不出现摇杆。

理解完成只展示语义确认，不展示惊吓脚本：例如“你喜欢红色电吉他；你不安的是深海里看不清的巨大事物”。提供“就是这个意思／修改”。歧义出现时只问最关键的一项，如“你说的苹果，是水果还是品牌？”；模型自报置信度不能替代这个判断。

抽象表达可显示“我会用逐渐消失的存在痕迹表达‘被遗忘’”，让玩家确认表达方向，但不剧透具体照片、出现房间和反转时机。如果需要将巨物表现为远景或模型，确认该转换而不是强迫改原词。

多个主题都保留；界面显示本局将覆盖哪些、哪些需下一局或额外准备，玩家确认后才能缩减范围。初期默认每栏一个主主题不等于输入只能一个名词。

确认后显示真实准备阶段：理解完成 → 场景适配 → 生成素材 → 动作与性能检查 → 准备就绪。显示子任务实际进度，不把模型生成 100% 当整局完成，不承诺未经实测的固定等待时间。

生成失败保留原文、解释及任务，不让玩家重新填写；提供查询进度、针对失败项重试、修改表达、返回。可提供显式“预设试玩”，但这是独立试玩模式，不计为专属生成成功。按用户提出的延后出场策略，语义已确认、生成作业已登记、开场区与后续槽位通过检查后，可先开始开场区；完整语义和表现覆盖门槛改在首次进入个性化区域前检查。后台准备不代表个性化已完成，不悄悄跳过未完成主题。

## 4. 总体管线：先拟案，后用真实能力定案

```text
自由文本 → 语义图 → 玩家确认 → 表达方案候选
                          ↓
空间机会与预算 ←→ 暂定内容计划＋资产配方
                          ↓
缓存命中／生成任务图 → 下载与检测 → 真实能力清单
                          ↓
确定性适配＋空间复验＋语义覆盖检查
                          ↓
开场计划冻结并先行游玩 → 后台素材验证 → 个性化区域绑定提交 → 两层游戏运行
```

关键区别：不能只根据模型承诺的能力先锁死剧情。保留已有“先空间、后结构机会、再内容匹配”的 PCG；规划先使用可验证的资产包络和能力需求，产物返回后再确定最终表现变体。缺少头骨或死亡姿态时，在进入游戏前更换兼容表达或重新准备；不能删掉猫死亡表达后继续称 CAT01 完成。

同一确认主题先准备多种合法场面候选，提高落位成功率；未满足覆盖时有界地改组合、尝试其他既定房型种子或经同样验证的布局。不得增造未经允许的房间轮廓、堵住门、伪造回访。达到上限仍不能兑现时停止开局并解释，不能让规划静默返回一个完全无关的梦。

正式开局冻结语义、地图拓扑、槽位包络及场面候选；已开放区域的计划与资产不可修改。未开放个性化区域允许在限定候选中绑定验证后的资源，形成带版本的 manifest 补充提交；不得改写已发生的事实、门连接或通行条件。区域开放后锁定资源；更晚的结果进入缓存或下一局。死亡、回访、假醒复用同一确认解释与已登记作业，不发起重复生成。

### 4.1 延后首次出场：利用开场游玩准备素材

用户已明确允许调整房间生成规则，让喜欢或恐惧主题不直接出现在第二个房间。本方案将“第二个房间”定义为从出生卧室出门即可到达的任意房间，而不是数组下标、房间编号或玩家第二次进门。

**硬规则：卧室的图距离为 0，所有图距离为 1 的邻接房都是开场区，不装配输入主题；最早在图距离至少为 2 的区域出现。** 开场区可有生活陈设、操作教学和游戏自带的轻微异常，但不承担尚未准备好的个性化内容。若自带内容恰好与玩家主题重合，也要排除相关物件与关键声音，避免“随机蜘蛛”提前兑现害怕蜘蛛。匹配检查依据已确认语义和资产标签，不以运行时模糊扫描代替。

隔离必须覆盖透门视线、窗户、镜面、监视器、影子和声音传播；不能人还在第二间房就看见第三间的主题物。必要时在生成时选择已有转角、凹室或关闭的门形成遮挡。隐蔽待提交区没有模拟实例、音源、可见占位或触发器，避免提前记录观察、提前追逐。

建议流程：

1. 玩家确认理解后立即提交生成；开场区资源使用本地已验证内容，不等模型全部完成。
2. 卧室起身、环顾、开门、探索相邻房间期间后台工作。正常操作教学与已有场面提供体验，不插入为等下载而设计的搜集任务或强制听完整段旁白。
3. 规划时在开场区之后预留足够的主题槽位、回访关系与观察位置；所有通往尚未就绪区域的入口构成加载边界，不能只有主路线一扇门检查、侧路却可绕入。
4. 通过文件、能力、空间及本机加载检查后，在遮挡后原子创建区域实例、绑定素材并解除加载边界。下载完成不等于 shader、纹理与动画已准备好；首次进入前还要完成必要预热。
5. 玩家提前抵达时，门交互给出明确“后续梦境仍在准备”的状态和重试／返回选择，保留回到开场区探索的自由。不假装要找钥匙，不无限提示“打不开”，不把准备失败计为玩法死亡。

房间距离只保证出场顺序，**不保证准备时间**。先测最快穿行时间与生成 P50/P95，再决定是否把默认首现距离提高到 3 或增加正常自带场面；不承诺两间房能覆盖全部生成耗时。移动性能、冷缓存、排队与复杂绑定均会影响结果。

危险不在加载边界前启动，不让玩家被追逐到尚未开放的门。第二层资源亦可在第一层准备，但首次个性化体验必须在第一层已有兑现，不把所有主题推到结尾。后续资源仍未就绪时在自然转场处明确等待，而不是临时改图或漏掉主题。

新增检查项：所有出生邻房无主题；从开场区无法提前看到或听到主题；快速冲刺、侧路与回头不能绕过边界；后台成功／失败、暂停、死亡和页面恢复不重复建任务；实例提交失败可回滚且不写观察事实；已开放对象不热替换。记录后台准备被实际游玩覆盖的时长、边界等待率与等待时长，以验证策略是否确实改善体验。

### 4.2 与正在实施的 UI 接口衔接

UI 任务交接的接口为 `prepareDream({like,fear},{signal,onProgress})`，进度枚举 `understanding/generating/preparing`，返回 opaque session 后调用 gameplay `start(session)`。取消、重试、旧请求隔离由 UI 管理；没有供应商时明确未连接。上述为协作方报告，本轮未复验其代码。

UI 任务已确认提前交接约定：prepareDream 返回非空 opaque session 表示开场可进入，不表示全部生成结束。界面使用“开场已就绪／可以先进入，门后的梦境仍在准备”。session 仍由服务／玩法方解释；gameplay 负责后台作业订阅、个性化区域 ready 检查与加载边界反馈，不要求 UI 理解供应商任务。

所有权移交顺序：`adapter.start(session)` 成功后调用 `generation.handoff()`；随后 UI dispose／cancel 不 abort 已移交作业。启动失败时输入页仍持有 session 供重试，不重复创建生成作业；未入梦时返回修改才 abort 当前准备。浏览器请求中止不代表供应商任务已取消，远端处理仍遵循持久账本规则。以上为已协调接口契约，UI 任务计划据此修改；本轮未复验实现，玩法侧后台生命周期与区域边界仍待接入。

UI 任务独占 `src/ui/`、`src/input/`、`ui-preview.html`、`tests/ui/`；本设计任务不修改这些路径。

## 5. 数据协议：身份开放，能力可核验

新增版本化契约，以下是项目内部提案，不是供应商原生字段：

```json
{
  "schemaVersion": 2,
  "inputRevision": 7,
  "entities": [{
    "entityId": "entity-1",
    "role": "like",
    "label": "红色电吉他",
    "kind": "physical-object",
    "attributes": {"color": "red", "material": "painted-wood"},
    "mustPreserve": ["electric-guitar", "red"],
    "excludedTraits": [],
    "candidateAffordances": ["display", "repeat", "emit-sound"]
  }],
  "relations": [],
  "ambiguities": [],
  "confirmation": {"revision": 7, "acceptedEntityIds": ["entity-1"]}
}
```

label、subject、attributes 可描述新事物；kind、角色、操作符等字段使用受控类型。未知名词不是未知执行命令。候选 affordance 是语义建议，不能直接写入 verifiedCapabilities；后者必须绑定实际文件／渲染适配器／音频验证证据。

AssetRecipe 保存主体语义、表达方式、风格、房间主题、目标包络、原点朝向、状态需求、精度档、必要能力与费用预算。AssetManifest 保存 contentHash、assetId、真实包围盒、材质、骨骼映射、clip IDs、采样点、性能统计及验证版本。

DreamManifest 保存 confirmedSemanticsHash、解释版本、planHash、资源 hash、内容版本、规则版本、质量档和所有输入到实体／场面绑定。复现依据完整 manifest，不依赖相同文本再次调用模型恰好返回相同东西。

保留 rawText 的短期私有草稿供玩家修改；明确会把输入发送到生成服务。向 3D 服务仅发送必要资产描述，不把全文写进 URL、公开文件名、分析日志。恢复任务和保存游戏是两个系统，不把任务恢复误写成跨刷新存档。

## 6. 适配器与受限场面组合

旧的命名剧本继续保留原文与边界，同时新增可复用表达模板。不能为了“通用”直接把 CAT01 改成所有物件的死亡版本。

| 适配族 | 需要验证的能力 | 可组合表达 | 首次接入位置 |
|---|---|---|---|
| 任意静物 | 可辨轮廓、尺度、材质、合法支点 | 陈列、重复、供奉、缺席、位置变化 | 将 RI02 喜爱物槽泛化；新增通用陈列／缺席模板 |
| 人形／四足 | 骨骼、动作、头部可定向、姿态包络 | 转头、群体、经过、匹配威胁 | 替换外观适配器；按实际能力启用凝视和状态 |
| 蛇形／多足／飞行／水生 | 对应运动、表面约束、感知点 | 贴地行进、附着、盘旋、水下经过 | 专用 body profile；B09／B10 等需定义可用变体 |
| 植物／可破损物 | 同一对象的枯萎、破口、碎片或材质变化 | 回访损坏、蔓延、痕迹 | 保留 B03/B04 特有规则，新增经验证的变体 |
| 环境／空间 | 水面、雨景、雾、深度、光照、声音与通行边界 | 窗景、远景、压迫尺度、环境变化 | 扩展 B10/B18 等表现，不能直接生成任意碰撞关卡 |
| 声音／音乐 | 可播放音频、循环、空间声源、停止反馈 | 重复、叠加、错拍、骤停 | 音频资产链与 B02 类模板；无声不得通过 |
| 抽象关系／感受 | 主体、关系与可感知对照 | 缺席、错认、被观察、重复、边界侵入 | 从 AB02/RI01/ID 等语法发展新变体，单独编号验收 |

受限场面描述只允许已实现操作，如 SpawnGroup、SetVariant、SetVisible、MoveAlongPath、LookAtTarget、PlayAudio、SetLighting、EmitFact。动作名称是待实现契约示例；实现前不能直接入池。禁止代码字符串、任意资源 URL、无限循环或模型指定碰撞坐标。

每个模板声明槽位、前置事实、触发、持续／终态、复位、互斥、注意力、危险权限与上限。编译器拒绝未知操作、缺资产、无终态、错误跨层读取；执行复用现有 story／flow，不另建一套状态机。LLM 可组合已验证模板和有限参数，不能在线创造新的追逐规则或新增死亡条件。

旁白继续通过 lineId 和事实守卫。新主题优先复用语义中性的已审台词；确需主题词时采用有边界的模板变体并登记版本。不能把“猫都倒下了”配给吉他，也不能用旁白声称本不存在的个性化表现。自由生成整段台词及实时语音不作为首条链的前置。

## 7. 3D、动画、声音及场景生成

### 7.1 3D 与动画

以 Tripo v3 作为拟定 3D 接口基线：创建文本转模型任务、查询结果、服务端保存文件；动态物体按需追加 rig-check、rig、retarget。官方当前公开了多种非人形绑定类型，但不代表本项目动作已适配或账号已验证。[文本生成](https://developers.tripo3d.ai/en/docs/quick-start)、[绑定检查](https://developers.tripo3d.ai/en/docs/animations-rig-check)、[自动绑定](https://developers.tripo3d.ai/en/docs/animations-rig)。

生成版本与绑定版本分别锁定；不要沿用默认绑定版本处理所有动物。几何减面／拓扑处理安排在绑定前，后处理若破坏骨骼就重新验证。根位移由游戏控制，动画默认原地循环，防止动画和寻路双重位移。

处理流水线：格式／外链／解码限额 → 包围盒归一化 → 朝向与可见表面检查 → 必要减面与贴图压缩 → 骨骼／动作验证 → 全动画包络 → 桌面／手机变体 → 场景适配。GLTFLoader 支持对应压缩扩展时仍需显式配置解码器，不能把文件“能解析”当全部完成。[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)

不能用 LLM 输出“有头部关节”作为证据：检查骨骼名称与层级、抽样动作、穿插、支撑高度；语义识别可用多视图模型辅助检查，仍保留人工样本复核。模型像不像玩家输入与动画能否运行是两个独立判定。

同一物件的前后状态优先从同一基础网格派生，保留 entityId 和外形特征；独立生成两个近似物不能默认当成“同一个物件”。枯萎、撕裂、死亡、塌陷不是一个通用变暗 shader，必须验证对应适配器。

### 7.2 体型与危险

将 THREAT_BODY 拆为可验证 BodyProfile：运动类型、半径或多段碰撞包络、高度、视线点、手电命中采样点、攻击距离、可通过门洞、动作最大边界。规划、感知、碰撞和表现共用它。

蛇需要贴地视点与身体路径；大体型可选择远景／局部展示，不能无限缩小到不再可辨。改变危险体型必须重新校验路线与安全示范，不可只换模型。未通过危险能力验证的主体可以作为无伤害场面出现；如果玩家确认的是特定追逐表达，改成静态需重新确认，不能偷偷降级。

### 7.3 抽象、音乐与环境

不把所有输入都发送给 3D 供应商。声音类建立独立 AudioRecipe，含声音身份、原创音色描述、时长、循环点、声源角色与事件用法；供应商通过音频适配接口选择，首次接入需实际音质与循环测试。本轮不指定未经核实的音频产品或恢复此前被否定的合成音效。

环境类由 LLM 输出有限主题参数，运行时拼装已实现的窗景、水体、雾、灯光及空间音源；新外观可生成纹理或远景素材。抽象关系由语义图映射情境，不靠模型生成一个叫“孤独”的物件。若确认输入的核心依赖声音，音频缺失必须阻止标记为完整个性化结果。

## 8. 后端、任务、缓存和费用

建议先用 Node 服务＋SQLite 持久 ledger＋独立作业 worker＋本地资产目录，后续部署换对象存储与队列；Vite 继续负责客户端开发。手机仅调用项目服务和加载优化资源，不在手机上运行模型或持有供应商密钥。

拟定项目接口：

| 接口 | 职责 |
|---|---|
| POST /api/interpretations | 接收 revision 与原句，返回结构化解释／歧义 |
| POST /api/dream-jobs | 引用已确认解释，服务端验证 revision、范围与预算后建任务图 |
| GET /api/dream-jobs/:id | 返回持久阶段、必要能力缺口、实际进度及错误 |
| POST /api/dream-jobs/:id/retry | 只恢复已有查询或明确失败节点，不整局盲重建 |
| POST /api/dream-jobs/:id/cancel | 停止未提交节点；远端已提交任务按供应商真实能力处理 |
| GET /api/dream-jobs/:id/manifest | 只返回通过校验的 manifest，与会话授权绑定 |

所有返回携带 revision；旧结果不覆盖新草稿。账本记录请求摘要、供应商任务 ID、依赖、模型版本、作业阶段、费用与产物 hash。事务唯一键阻止并发重复提交；提交响应丢失进入 submissionUnknown，先核对原任务，无核对能力则停止自动付费重试。

区分供应商 success、下载成功、资源验证通过、场面就绪。超时不代表失败，未知状态不当成功；用户离开页面不代表远端取消。官方同样要求异步查询、终态检查和超时处理。[任务生命周期](https://developers.tripo3d.ai/en/docs/task-lifecycle)

缓存以规范 recipe＋生成／后处理版本为键；精确匹配和经认可的主题兼容缓存分开，不能拿普通黑猫缓存代替明确的白色三脚猫。私人解释按会话隔离；下载地址仅服务端短期使用，验证产物用稳定内部地址。

每局预算按解释、3D、绑定、动画、音频／图像、后处理和重试累计，不能只算两个模型。配置“并发作业数、总费用、最大重试、准备截止时间”；未取得账号实际定价前不填虚假的每局金额或几十秒完成承诺。模型生成成功但游戏适配失败，仍可能产生费用，应计入失败成本。

## 9. 手机与资源预算

同一语义 manifest 派生桌面／手机资源档，不改变剧情含义。手机优先：较低面数与贴图、共享静态实例、受控骨骼数量、低频远处动画、降低反射与后处理成本。双摇杆和新资源加载共用暂停／转场屏障。

首轮测试起点：主展示物 1–2 万三角面、群体单体 1–3 千、主贴图 1024，尽量合并材质；它们是本项目提案，不是供应商保证或最终性能标准。群体总预算按实例数量和状态共同计算；蒙皮对象不能直接当普通 InstancedMesh 复制。压缩磁盘字节与解码后纹理／GPU 内存分别测量。

动态加载失败保留当前安全开场区或准备界面，不进入未完成区域。后台下载、解码和 GPU 上传限制并发并分帧处理，避免准备素材拖垮当前移动手感。手机连续约十分钟实测帧时间、峰值内存、发热和后台恢复；WebGL 资源重建从已提交 manifest 恢复，不重新生成模型。音频解锁在主动开始时完成；音频是主题必要能力时，解锁失败需提示处理，不能无声宣称兑现。

## 10. 实施顺序与文件交接

不等 57 项全部完成后才接服务。建议按下面的纵向切片推进，每项单独任务卡并保留既有流程回归：

| 批次 | 具体交付 | 通过条件 |
|---|---|---|
| G0 契约与入口 | 新语义 schema、revision、确认 UI、任务状态；预设映射只保留测试模式 | 新名词能走到待生成配方，不因字典缺项被拒绝；假服务结果不得宣传真生成 |
| G1 任意静物真链 | 真实解释＋Tripo＋持久任务＋下载校验＋GLB＋通用 RI02 槽 | 测试前未知的名词，在不改源码条件下进入正常局并能辨认；刷新恢复同一作业 |
| G2 状态与语义适配 | 通用重复／缺席模板、材质兼容变化、同物件跨状态、覆盖门槛 | 新主体不只有孤立模型；前后变化与玩家原意一致，死亡保留 |
| G3 动物与威胁 | BodyProfile、绑定、动作、感知点和路径验证 | 至少四足、蛇形、人形分别正常移动与反制；不能用三种人形皮肤充数 |
| G4 抽象／环境／声音 | 情境组合、主题参数与音频资源链 | 深海、被遗忘、音乐等类别有实际表现；文字说明不能代替效果 |
| G5 移动端与发布门槛 | 资源档、双摇杆、失败／恢复、完整开放输入评测 | 真机两层通关；记录准备成功率、失败成本和性能，不仅演示固定缓存 |

G1 是首条证明链，不代表开放输入整体完成；完整目标包含 G2–G5。固定场面完善可继续，但不抢占自由输入的核心排期。接口建议落到：`server/interpretation/`、`server/jobs/`、`server/providers/`、`server/assets/`、`src/personalization/`、`src/assets/`、`src/presentation/adapters/`；实际目录由程序任务认领时确定。

需迁移的调用点：fear／like 的身份枚举、content-tokens、state、main 确认流程、content-catalog 资格、content-fit 的物件二选一、validate 的白名单、story-proxies 固定对象、threat-profile／感知／空间拟合。不要只删除旧校验而让任意输入绕过能力约束。

## 11. 验收：证明开放输入而非预设演示

建立覆盖具体物件、生物、虚构形态、环境、声音、抽象关系、复合、否定、歧义的测试集，每类至少 10 条；另保留开发时未用于提示词调优的盲测输入。样本有限，不能据此数学证明所有文本都成功，但可以发现依赖词典和缓存的假开放。

每条记录五层结果：解释忠实 → 计划合法 → 资产可辨且能力满足 → 游戏内确实发生 → 真人体验与性能。拒绝、歧义澄清、超时和降级单独计数，不从成功率分母删掉；提供逐类别结果、P50/P95 准备时间、冷／热缓存、费用和人工干预率。

必须覆盖：同物件不同角色、否定词、多个主题、修正中旧请求返回、并发双击、提交结果丢失、取消后迟到结果、GLB 外链／超预算／无骨骼、声音缺失、没有合法落点、手机号等无意私人输入不进入公开文件名。死亡／假醒／回访／暂停不能创建新作业或改变已确认主题。

产品验收硬门槛：已确认主题不能无说明地遗漏；不能用其他词的预设冒充；没有能力证据的危险模型不能入局；每个新词不需新增源码分支。最终成功率阈值在真实小样本费用和延迟测量后确定，不预填未经验证的 100%。
