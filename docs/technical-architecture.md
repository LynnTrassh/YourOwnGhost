# 技术框架

版本：v0.1；日期：2026-10-30。依据 [GDD v0.2](game-design-v0.2.md) 与 [剧本总集](script-catalog.md)。本文定义目标架构与实施顺序，不代表模块已实现。

## 1. 范围与当前基础

使用 Three.js、Vite、JavaScript ES Modules，面向桌面浏览器键鼠单人游戏。实际依赖版本由 package-lock.json 固定。完整范围包括 57 项场面、主流程、三类威胁及五类行为回应；分批交付不删减范围，单局只编排其中一部分。

当前 src/planning/ 已实现每层 8–12 间房的随机共墙连接、结构机会识别、内部布局、通行校验与保底；src/story/ 接入猫群观察回访与左右门建议的灰盒状态和无声字幕；src/flow.js 接入两层地图、唯一假醒、普通死亡同层返回、起身宽限、结束与跨层状态；src/main.js 串联输入、暂停、移动和渲染；src/world.js 按计划装配场景并消除重复可见墙面；src/collision.js 提供碰撞与移动。src/threat.js 已接入第二层凝视雕像的安全示范、真实手电判定、有视线时跨房追踪、遮挡停追、照停时持续转向与接触死亡；也保留调试地图死亡入口。现有工程尚无完整随机内容组合、B13–B16 连续追逐剧情链、语音或生成服务。下文仍为完整技术目标，具体完成证据以开发记录和任务卡为准。

## 2. 模块与所有权

以下为计划模块边界，可使用普通 ES 模块与函数实现，不引入通用 ECS 或复杂消息中间件。

| 模块／计划目录 | 拥有的数据 | 职责与禁止事项 |
|---|---|---|
| flow/ | 流程阶段、转场事务、暂停原因 | 管理开始、起身、探索、死亡返回、假醒、结束；不能直接改剧本阶段 |
| state/ | 可序列化 RunState、配置版本 | 创建新局、提交状态变化、提供只读快照；不保存 Three.js 或 AudioNode |
| simulation/ | 游戏时钟、事件序号、更新顺序 | 在统一步进中执行规则，暂停时不推进游戏时间 |
| perception/ | 当前视线与连续曝光缓存 | 计算有效观察、光照感知、转开回看；不能自行触发语音 |
| scripts/ | 剧本定义与实例阶段 | 根据事件产出受限状态变更、表现命令和旁白请求 |
| facts/ | 不可变行为事实与派生查询 | 记录真实动作、目击、建议呈现；不记录猜测的人格与动机 |
| narrative/ | 消费记录、互斥、评论预算、当前句 | 校验条件、调度旁白与字幕；不能伪造事实或改变危险规则 |
| planning/ | 内容计划、节奏与空间关系图、房型布局、梦层计划、验证报告 | 分阶段生成并校验纯数据计划；不直接创建场景，不在重进房间时重新随机 |
| threats/ | 威胁实例、感知、路径、追逐阶段 | 持续更新连通区域的威胁；不依赖模型是否在场景中 |
| presentation/ | 场景、模型、动画、渲染目标 | 将已提交状态表现出来；卸载不删除世界状态 |
| audio/ | 音源、声道、播放游标 | 空间声音、旁白、字幕时轴与关键声音窗口；旁白不产生世界噪声 |
| assets/ | 资源清单、加载任务、缓存引用 | 验证资源能力、加载、回收；静态模型不能冒充动画能力 |
| services/ | 服务适配与项目任务状态 | 语义和资产服务的受限输入输出；密钥仅在服务端 |
| debug/ | 独立预览会话、诊断视图 | 指定剧本、种子和阶段，展示失败原因；不得污染正常局 |

main.js 最终只负责组装模块、连接 DOM、启动循环和释放应用。模块间通过普通函数调用和有类型字段的事件交互，业务模块不直接查找 DOM。

### 随机地图管线在架构中的位置

地图生成由 `planning/` 负责，位于已确认偏好与运行时世界之间。主链为：

**确认偏好 → 按既定房型库生成空间与门连接 → 识别结构机会 → 匹配剧情并校验依赖与节奏 → 放置内容与内装 → 复验与确定性重试 → 提交梦层计划 → 加载场景。**

| 边界 | 数据交接与职责 |
|---|---|
| `services/` → `planning/` | 提供经过玩家确认的语义解释；没有服务时使用明确标注的本地映射。已确认结果固定，布局重试不重新请求 AI |
| `planning/` 内部 | 内容选择、关系生成、房型装配、内容落位、验证各自形成可检查的中间结果；具体阶段和字段见 [生成流水线](room-generation.md#3-生成流水线) |
| `assets/` ↔ `planning/` | 提供可用能力、占位尺寸和资产包围盒；生成器产出资产需求和绑定。生成模型的随机性不决定地图连通性 |
| `planning/` → `flow/`、`state/` | 返回校验通过的 `LayerPlan` 或结构化失败报告；流程系统确认当前 runId／transitionId，再一次性提交完整梦层，失败不写入半张地图 |
| `state/` → `scripts/`、`threats/` | 按已提交计划创建剧本实例、事实关联与威胁路径。运行器判定事件，不能在此重新抽取房间或剧本 |
| `state/`、`assets/` → `presentation/` | 根据同一计划构建 Three.js 场景、碰撞表现与声源；加载顺序和房间卸载不改变布局或剧情身份 |

几何生成采用固定的 11 种九宫格轮廓库，先随机紧凑拼接与开门，再识别可支持回访、配对、分叉与追逐的结构条件；不预排固定房间序列。房间形状与尺度以 R.E.P.O. 为参考方向，采用方形／长方形、L 形、带凹室、多出口、狭长连接和较大开放空间。多出口可与轮廓组合。门位、通行、观察、内容落点和遮挡区均由模板声明，具体比例待灰盒验证。

房型装配进一步分为外轮廓、门口位置、内部布局和装饰细节。内部布局由独立随机子流选择书架、隔断、柜台等结构组合，写入统一障碍数据；装饰子流只能改变外观。planning 基于墙体与家具共同生成可通行图，presentation、移动碰撞和调试地图共用该计划。当前内部布局实现见 [房间内部布局与装饰](room-generation.md#12-房间内部布局与装饰)。

开局确认整局内容计划，生成第一层和第二层空间骨架；假醒时依据真实事实启用第二层条件内容，不重新请求语义规划或临时抽取无关事件。普通死亡和回访直接使用已提交地图。B17／B20 等局部空间变化走第 6 节的图事务，不重新运行整局生成管线。

实施顺序为：随机空间连接与基础校验 → 结构机会识别 → 视线及行为条件检查 → 剧情匹配与组合校验 → 语义服务接入。当前图结构候选不等于已经验证左右建议、回访演出或追逐。所有阶段均保留版本、种子、尝试次数和验证报告，完成证据以生成结果及实际试玩为准。

## 3. 状态结构

```js
RunState = {
  schemaVersion, runId, seed, contentVersion, rulesVersion,
  preferences: { confirmedRevision, interpretation, planMode },
  flow: { phase, layerId, transitionId },
  plan: { planHash, layers, dependencies, reservedSlots },
  layers: { /* layerId -> graph, roomStates, scriptInstances, changes */ },
  facts: [],
  narrative: { consumed: [], branches: {}, behaviorCount: 0, behaviorKinds: [] },
  player: { roomId, position, standing, flashlight },
  transient: { threats: {}, chase: null, graceRemaining: 0 }
};
```

这是结构约定，不是可直接导入的代码。Map、Set 如用于运行优化，序列化时转为明确的数组／对象。每个剧本有 definitionId 与 instanceId；房间、对象组、台词、建议、追逐均使用稳定 ID，禁止用显示名称或数组当前下标关联。

| 操作 | 保留 | 清除／重建 |
|---|---|---|
| 离房／回访 | 布局、剧本阶段、变化、事实、消费记录 | 视线曝光、无效语音请求；可卸载表现对象 |
| 普通死亡 | 同层布局与永久变化、事实、语音消费、行为评论预算 | 当前语音、曝光、输入、追逐临时状态；玩家回床并给予宽限 |
| 假醒 | 本局消费记录、预算及允许查询的前层事实 | 活动层、玩家位置、临时威胁与场景；新层实例按条件启用 |
| 暂停／失焦 | 全部业务状态与当前语音游标 | 清理按键；冻结游戏时钟与播放，不发生剧情推进 |
| 新局 | 用户设置、可复用资产缓存 | 生成新 runId；清空本局事实、实例、预算和消费 |

CAT01 不跨层继承。IN04、B27、B28 与主流程使用明确的事实白名单查询；保留历史日志不意味着任意剧本可以读取任意历史。跨刷新游戏存档不属于首版，但数据必须可序列化用于复现；外部生成任务恢复与游戏存档是两件事。

## 4. 统一执行顺序

每个模拟步按以下顺序运行：

1. 接收输入；检查暂停和转场屏障；丢弃旧会话回调。
2. 更新玩家移动与碰撞，解析正常过门、交互和位置。
3. 基于更新后的视点、对象位置与遮挡计算观察、光照和声音感知。
4. 更新威胁，判定接触死亡。死亡优先于同一步的普通离房剧情：不得把死亡传送误记为 RoomExitedNormal。
5. 写入有序事实，驱动剧本状态机；校验后一次提交变化。
6. 根据提交后的阶段和事实产生演出与旁白请求，进行优先级和有效性检查。
7. 同步模型、动画、灯光、音源和字幕，最后渲染。

采用有上限的模拟步长与固定顺序；页面恢复不追赶隐藏期间的时间。游戏时钟负责曝光、停留、延迟和追逐；真实时间只负责网络超时及外部任务。网络完成可以写缓存，但暂停期间不得推进游戏演出。

异步任务携带 runId、transitionId 和资源所有者 ID。重开、死亡或切层后，只接受仍匹配的结果；过期模型加载结果释放引用，过期语音结果不得开始播放。AbortController 用于可取消请求，代际检查处理无法取消的回调。

## 5. 流程与安全示范

流程阶段为 preferenceInput → loading → waking → exploring → layerTransition／deathReturn → waking；第二层出口进入 ending。暂停是附加门禁，不另建丢失原阶段的“暂停局”。转场只允许一个事务占用控制权，连续按键不能重复切层或重复结算。

威胁安全示范拥有独立的 presentationBarrier。语音可用且开启时，以示范句结束作为屏障的一部分；静音、播放失败或字幕关闭时，以同等演出窗口和可见规则示范完成作为替代。窗口使用资源清单的 authoredDuration，不依赖浏览器音频加载成功。玩家始终可以移动；离开示范区域则关闭该区域伤害，回到合适位置后完成剩余示范，避免语音取消直接放开危险。

正式危险开放需同时满足：示范已完成、玩家在有效遭遇区、可通行逃生路线成立、死亡宽限结束。死亡后不重播示范句，使用已记录示范状态与新的起身宽限。

## 6. 空间、表现与持续逻辑

房间图、实体位置、剧本状态属于模拟层，场景树只是投影。默认加载当前房及必要相邻视听区域；跨房追逐继续更新相关路径和威胁。普通非追逐动画只在场景活动时推进。配对房和镜面中的被观察对象属于活动表现范围，即使玩家身体不在其房间。

B17、B20 等变更采用事务：构造新连接与碰撞 → 验证玩家／威胁落点及出口 → 预备表现资源 → 同步提交 graphVersion、门、碰撞、路径与画面。失败保持原状态并记录原因；不能先移除门模型再发现出口断开。旧版本寻路结果必须丢弃或重算。

镜面、监控、延迟替身与形变分别实现表现适配器。ME02 保存有长度上限的姿态历史；镜像差异由场景层与可见性配置实现，不反向修改真实房间。资源采用引用计数或明确所有者，释放纹理、几何、音源、渲染目标和监听器，不能把共享资源随一个房间销毁。

当前恐惧选择由 `src/personalization/fear.js` 输出规范化的 `state.fear`：版本、来源 `local-preset`、预设 ID、显示名、appearanceId 和 behaviorId。原始句子仅留在输入控件中，不写入 URL、存储或运行日志。确认前是界面草稿；确认后创建新局，不在演出中途换外观。死亡和切层不覆盖 `state.fear`；场景重建明确传入 appearanceId，同种子重玩复用本局选择。未知预设或外观 ID 拒绝装配，不静默改成石像。

`src/threat.js` 的默认行为是 `gaze-pursuer`；`src/rendering/threat-proxy.js` 根据 appearanceId 装配通用、人偶或小丑简模，不反向写入行为状态。当前共用 `src/threat-profile.js` 的人形包络：半径 0.24 米、高度不超过 1.68 米、头部视线 1.54 米、照停目标 1.3 米、正面朝 +Z。测试检查模型包络、照停目标处可见网格及资源释放。既有 `statue-*` 实例名与台词消费键保留为兼容标识，不代表材质约束。未来非人形外观必须有独立、经验证的感知点及形体适配；这次接口拆分不等于已经支持蛇形、四足或远程 GLB。

听声者灰盒已有显式 `?threat=hearing` 的第二层运行路径：`src/player-noise.js` 从碰撞后的实际位移产出世界脚步，`src/threat-hearing.js` 通过房间图和当前关门状态筛选事件，只朝最后声源寻路并停步搜索；`src/threat.js` 分派行为，默认地图仍使用凝视型。听声者首次感知后的移动和字幕窗口属于无伤害示范，死亡重置搜索但保留示范记录。该路径用于隔离验证，未进入默认随机池；代理外观、实际录音、第二层自然遭遇与 B13–B16 完整追逐均未验收。

避光者灰盒由 `src/planning/avoider-fit.js` 在现有房间中预约可见、可达的后退点，规划校验拒绝不合法点；显式 `?threat=avoider` 将它用于第二层，`?preview=TH03` 可从合法观察位隔离验证。`src/threat.js` 在实际照见后启动无伤害后退示范，示范结束后按手电照见状态后退或靠近，接触仍须无遮挡。默认随机池不变；正常路线、正式外观与录音及连续追逐组未验收。

## 7. 声音与资产边界

音频分 master、narration、world、critical、ambience 总线。critical 由脚步、撞门、碎裂、祝福等演出声明独占窗口；旁白调度等待有效空隙，过期则丢弃。空间音频由真实声源位置与房间连接决定；旁白为非空间评论，不进入听声者的感知事件。

当前已撤下合成占位音效：`src/main.js` 不再导入声音模块，不创建 AudioContext 或播放节点，菜单不显示音量控制。`src/audio/director.js` 的事件／空间混音原型、`src/audio/output.js` 的合成输出试验及其测试暂留在源码中，均不接入运行版本；其测试通过仅证明技术行为，不能代表音色通过试听验收。`src/audio/asset-output.js` 已提供录音清单校验、浏览器解锁、按需解码、分总线播放、静音、暂停续播及迟到回调失效接口；仓库尚无可用录音，运行入口未接入，故此接口通过自动检查不代表 S05 声音体验完成。旁白继续使用字幕，安全示范和威胁状态不依赖音频。后续选用符合场景材质的脚步、石头摩擦及克制的环境录音，逐项试听后接入；不以电子音高滑动代替猫叫，也不默认加入死亡／逃脱的旋律提示。正式语音、门洞声传播和独占窗口调度尚未实现。

AssetManifest 保存 assetId、版本、文件地址、校验摘要、尺度、朝向、包围盒、材质与动画能力、授权记录及预算。剧本要求能力而不硬编码文件名：例如 deadPose、headLook、clothCollapse、delayedPose。缺少能力时不能仅凭 GLB 可加载判为剧本可用。

资源加载失败保留适配的占位表现，并明确当前使用占位；对象身份和剧情阶段不变。生成服务创建使用持久幂等键，超时先查询原任务；停止等待只切换本地表现，不等于取消远端任务。每局最多两项生成任务；服务版本和账号接入另在实际实现时核实。

## 8. 实施顺序与完成证据

下表保留完整能力依赖；当前迭代优先级按 [剧情分池与探索内容编排](content-scheduling.md) 第 7 节执行：先建可用内容登记、实例分配与覆盖诊断，接入自带短场面及主要事件，再兑现喜欢输入和跨层呼应，之后扩展完整危险与特殊表现，最后接真实生成服务。通用模型加载随场面交付逐步接入，不先于内容密度单独扩张。新的来源资格、角色与拒绝原因扩展既有 ContentPlan，不另外维护一份会在回访时重抽的房间配置。

| 顺序 | 修改范围 | 验收 |
|---|---|---|
| 1 | 从 main.js 拆出时钟、流程和状态所有权 | 现有移动、碰撞、开门、暂停与重开回归通过 |
| 2 | 事件、事实、剧本实例、观察及旁白调度 | CAT01 全路径、静音、失败播放、死亡中断和续播可复现 |
| 3 | 房间图与内容编排 | 自然回访、左右合法路线及对应评论成立 |

旁白与真实行为回应在首个闭环内交付。所有模块保持可用纯数据进行测试；Three.js 与 Web Audio 通过适配层隔离。测试不得只复述实现，要覆盖错误路径、状态边界和并发回调失效。

诊断至少输出 seed、planHash、版本、事件序号、实例阶段、触发拒绝原因、语音消费键、评论预算、图版本和资源计数。语义理解与资产生成不得默认记录完整个人输入。性能预算先记录目标设备、帧时间、加载延迟与内存，再确定阈值，不将估计写成通过证据。
