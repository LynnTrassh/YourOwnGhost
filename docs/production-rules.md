# 心里有鬼 制作与技术规则

本文与 [游戏设计文档 v0.2](game-design-v0.2.md)、[剧本总集](script-catalog.md) 共同定义项目设计。这里只列制作要求；实际完成情况见 [开发记录](development-log.md)。

## 1 内容分类与范围

CAT01、28 个扩展剧本、B01–B28、主流程旁白、三种威胁行为及其旁白、五类 Meta 行为回应全部纳入制作。分批实施不等于可选或取消，每局只抽取部分内容。

| 编号 | 主题 |
|---|---|
| T01 | 喜爱物过量 |
| T02 | 喜爱物毁坏 |
| T03 | 注视与异常行为 |
| T04 | 恐惧物遭遇 |
| T05 | 追逐与逃生 |
| T06 | 空间失常 |
| T07 | 声音与窥探 |
| T08 | 喘息、假醒与记忆 |
| T09 | 替身与身份错位 |
| T10 | 镜像与媒介差异 |
| T11 | 侵入与污染 |
| T12 | 仪式与被指定的位置 |
| T13 | 尺度与身体异常 |
| T14 | 时间与因果错位 |
| T15 | 缺席与消失 |

主题可叠加，建筑用途、素材和空间组合是不同维度。组合为 C01 独立房、C02 回访房、C03 配对房、C04 连续房组、C05 跨梦层呼应。单向观察、影响传播、双版本对照、前后状态对照是附加标签，不另算剧本。

## 2 共用能力与制作批次

先具备独立剧本状态、有效观察判断、空间关系编排、单事件关注管理、旁白调度与场面预览，再逐批接入内容。出口不要求搬运物件或集齐可选事件；主要演出布置在自然必经路上。

| 批次 | 能力 | 扩展剧本 |
|---|---|---|
| 第一批，共 12 项 | 群体、状态切换、简单动作 | ID01、ID02、ID03、ID04、RI01、RI02、RI04、BO01、TI02、AB01、AB02、AB03 |
| 第二批，共 8 项 | 声音、影响传播、时间编排 | IN01、IN02、IN03、IN04、RI03、TI01、TI03、TI04 |
| 第三批，共 8 项 | 独立视图、形变、专用美术 | ME01、ME02、ME03、ME04、BO02、BO03、BO04、AB04 |

CAT01 先建立完整观察、离开、回访与死亡保留能力。第二批同时完善 B13–B16 的跨房连续追逐。基础场面按共用能力接入，但 B01–B28 均须逐项验收。首个玩法闭环同时验证主流程／猫房旁白与路线行为回应，不将叙事系统推迟到全部美术完成之后。

统一制作状态为：待制作 → 灰盒可演示 → 视觉音频完善 → 已验收。另行记录设计细化、程序实现、配音录制及验收证据；不能用一项完成代替全部完成。

## 3 状态、空间与调度

- 持久状态保存种子、梦层、布局、剧本阶段、已提交变化、行为事实与语音消费记录。临时状态保存受伤、追逐目标、输入与交互计时。渲染对象可以销毁重建，但不得重新抽取剧情或清空持久状态。
- 房间壳体定义门、窗、观察点、道具与怪物落点；点位与房间绑定，内容只在合法点位中随机。固定种子复现结构、剧本及落点，普通死亡不重抽。
- 进入、有效观察、正常离开、再次进入、死亡传送、剧情假醒分开处理。有效观察同时考虑视角、遮挡及连续时间。初始场面未被看见时，不消耗后续变化。
- 单次变化提交后保留；持续运动只在场景活动且游戏未暂停时推进，回访恢复同阶段。离屏追逐是例外：威胁持续更新路径与位置，不因房间卸载而消失或暂停。
- 回访房提供短回路、支路回程或另一入口；配对房提供实际可用的视听联系；连续房组提供完整可通行路线。空间变化同时更新视觉、门、碰撞、导航与状态，不能半堵门、重复伸长或死亡后断路。
- 主流程引用和 IN04、B27、B28 才可读取声明过的跨层事实。选择这些剧本时同时选择前置事件，不凭空生成已经毁坏、沾染或被见过的物件。
- 剧本实例、阶段、语音与字幕使用稳定标识；数据清单与文字文档的同步规则在运行时接入前明确。未知行为、非法空间引用应拒绝或回退，不执行模型返回的代码。

### 房型装配规则

房间轮廓与尺度参考 R.E.P.O. 的空间方向，采用方形／长方形、L 形、带凹室、多出口、狭长连接、较大开放空间作为基础房型，完整用途见 [GDD 房间形状与空间关系](game-design-v0.2.md#房间形状与空间关系)。多出口可与其他轮廓组合。

- 每个房型声明轮廓、可开门墙段、可通行区域、观察点、内容落点和遮挡区域。具体尺寸与比例待灰盒调试，不将暂定尺寸写成最终标准。
- 先确定剧本连接需求，再选择兼容房型并装配门窗与内容。外形合适但无法提供回访、视听联系或连续逃生的房型不能用于该实例。
- 门位必须与实际房间连接一致；家具、群体及凹室内容不能堵住通道。旋转或调整房型后，门位、观察点和碰撞一并匹配。
- 分别验证猫房回访前后能看清群体、转角场面在预期位置显露、多出口分支可走、追逐绕行成立，以及大空间主体在目标距离可辨。
- 每种房型通过单独灰盒验证后，再验证其在组合地图中的通行、视线与剧本关系。当前基础场景不作为房型库或地图生成器已经完成的证据。

## 4 内容互斥与注意力

- 一次突出一个事件，不同时播多条旁白或塞入多个交互目标。真正的喘息房不追加惊吓，规则、地图和调试工具放入主动打开的界面。
- 避免连续两个群体注视或连续两次回访毁坏。镜像、监控、因果错位不在同一关注区叠加。
- CAT01 猫死亡和 AB01 猫消失不竞争同一对象组，不默认连续发生；AB01 不替代 CAT01。
- ID03 同脸合照、B05 刮脸照片、AB02 人物消失分别保留。毁坏、缺席、恢复是不同结果，不要求每条剧本经历全部状态。
- B27 与 B28 分开编排，避免床边争夺关注；B26 共用主流程卧室演出及播放记录。
- 三种威胁分别实现、逐项验收，每局优先突出一种。威胁示范句与 B13 起段句在同次首次遭遇中只选一句。
- 纯观看场面可以无按键、无伤害、无奖励。不能给每个异常自动加凶手、身世、搜集、机关、追逐或解释。不强制搬花灯，不每开门回床，不做无意义的永久走廊拉长。

## 5 模型、声音与特殊表现

程序化或本地占位模型先验证场面，再替换外观。人与替身使用游戏内角色，不要求玩家照片、身份信息或现实亲友声音；B24 使用开场听过的同一配音。

| 能力 | 制作要求 |
|---|---|
| 模型替换 | 只替换外形，不改变移动、碰撞和反制规则；静态 GLB 不自动提供绑定、口型、骨骼重定向或动画 |
| GLB 加载目标 | 检查格式、大小、真实内容、尺度与朝向；本地加载拒绝外链资源，规划 Meshopt 支持，尚需实现验证 |
| 群体与污染 | 设数量上限及回收策略；变化阶段独立保存，重新进入不恢复；溢出连续但不无限增长 |
| 镜像与监控 | 独立场景层、渲染目标、受控更新频率；侧移时保持正确视点关系，不能用静态图冒充镜子 |
| 镜面资源 | 房间卸载时释放渲染目标与音频资源；先验证目标浏览器的单效果性能，再考虑同时多个反射面 |
| 巨大局部 | 用窗框、距离和遮挡表达尺度，不暴露模型截断面，不要求展示完整身体 |
| 长身体 | 使用分段或骨骼运动，头部保持正常比例，不整体拉伸模型 |
| 呼吸墙面 | 家具不动，出口不封闭，碰撞与可通行范围保持可信 |
| 家具关节与被子 | 制作关节层级、形态变化或专用动画；不能用静态 GLB 或整床缩放代替 |
| 脚步与关键声 | 声源与空间关系一致；TI04 停步后额外三步、碎裂声、祝福声等不被旁白盖住 |
| 旁白 | 每条保存录音与字幕标识、条件和语气；全局一句、每阶段最多一句，行为评论每局最多两次且同类一次 |

## 6 个性化资产接入要求

语义规划确定素材与兼容剧本后，再提炼形状、材质、风格与用途用于生成。动物、花、音乐使用不同表达能力，不将任何输入都替换为带眼睛的同一种怪物。

- 服务密钥只留在服务端，浏览器持有项目任务标识；只发送所需资产描述，不发送整个偏好档案。
- 记录任务 ID、服务版本、参数、资产摘要与终态；恢复页面时衔接已有任务。网络超时不等于创建失败，禁止盲目重复创建收费任务。
- 查询存在超时与失败终态；未知状态不能当成功。临时下载地址不能作为永久资产路径，完成后保存并验证实际文件。
- API 版本在实际接入时统一锁定，创建、查询和结果字段不能混用版本；账号、额度与调用方式需在接入时确认。
- 失败、加载失败或玩家不愿等待时提供明确的占位方案。生成成功、文件下载成功、浏览器可用、适配动画分别验收，不承诺未经实测的等待时间或效果。
- 实验起点：每局最多两项生成任务，先验证一项；单资产约 20,000 面。它们是待测预算，不是最终性能标准，纹理和总体内存上限尚待实测。
- 首条链路验证创建 → 查询终态 → 保存 GLB → 加载 → 比例朝向归一化 → 材质检查 → 任务恢复记录。记录等待、下载量、实际面数、贴图尺寸、可见错误、帧率与实际费用。

## 7 预览与验收

提供可指定剧本、阶段和种子的本地预览入口，直接检查回访与死亡；预览改变状态时需明确，不能作为正常通关证据。调试说明不进入正常游玩界面。

每条剧本都检查：首次进入、未观察离开、观察后离开、回访、暂停恢复、普通死亡重进、假醒、新局。另检查门槽唯一、模型落点合法、出口可达、互斥有效、声音来源正确、台词不过期补播、不提前剧透、不重复消费、不引用不存在的行为。

B13–B16 必须完整连续逃生并验证失败复位；IN04、B27、B28 分别验证前置事实存在和不存在两种情况。五类 Meta 分支分别演示，不能因每局最多两次而少做其他分支。

全部剧本既能单独预览，也要在合法组合中发生。自动测试只证明状态与生成规则，真实输入、声画表现、恐怖感和约十分钟节奏必须实际试玩。配置有名字、生成出模型或只有截图都不等于验收通过。

## 8 尚待落实的参数

已确定演出与台词不应回退为泛泛候选。仍需落实的主要是观察范围、视线转开判定、快速离开的窗口、怪物速度与感知距离、关门延缓时长、死亡宽限、隐藏／失去视线判定、语音与字幕资源、总体性能预算及服务账号方案。

0.8 秒观察与主句后 5 秒停留为初始调试值；不能把调试值写成已通过体验验收的最终数值。新增或修改规则时同步更新 GDD、相关剧本条目及运行时配置。
