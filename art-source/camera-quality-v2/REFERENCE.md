# 《心里有鬼》— VHS 低照度录像后处理材质规范

> 用途：交给 Codex，在现有 3D 游戏中实现可调节、可关闭、低成本的全屏后处理。目标是匹配用户提供的 **2003 年凌晨、冷白荧光灯下的暗绿灰色走廊录像**，不是制作夸张的故障特效。

## 0. 先检查项目，禁止盲目改造

1. 检查当前引擎/渲染器、后处理管线、色彩空间、曝光和已有 VHS 滑杆；沿用现有技术栈，不要假设一定是 Three.js 或 Godot。
2. 保留当前场景、灯光、游戏逻辑、地图种子和 UI。先在独立测试场景或可回滚分支实现。
3. 先提供原画面 / 后处理画面同机位截图，再讨论是否作为全局默认。
4. 用户参考图为视觉目标，不把静态截图误认成真实 VHS 磁带的技术测量结果。

## 1. 参考画面视觉特征（按重要性排序）

- **低照度彩色摄像机感**：整体灰绿、棕灰、发脏的米白；不是纯绿色夜视仪。低饱和、黑位稍抬升但保留深黑；亮灯区域偏冷白，尽头门缝光微暖。
- **暗部彩色电子噪声**：阴影里有细小、非均匀、随时间缓慢变化的亮度颗粒和低强度彩色斑点；中亮部明显更干净。避免均匀铺满屏幕的白色雪花。
- **有限的细节解析力**：边缘轻微软化，暗部细节粘连，亮灯有轻微扩散；不要全局强高斯模糊。
- **轻度模拟视频特征**：少量水平色度扩散、微弱横向色偏、偶发的低幅度水平波动；不是常驻 RGB 三色分离。
- **克制的镜头特征**：极轻暗角与角落柔化。画面里的 REC、日期、时间是可选独立 UI 层，不属于场景材质。

## 2. 必须分层实现的处理链

按渲染管线实际颜色空间调整顺序，并记录原因。建议概念顺序：

1. **Scene linear HDR**：正常的空间、材质和灯光渲染；灯具亮度与房间黑暗关系必须先正确。
2. **曝光/色调映射与调色**：适度压缩高光；冷灰绿偏色、低饱和、暗部轻微偏绿棕；不损坏重要导航线索。
3. **摄像机低照度缺陷**：亮度相关的亮度噪声 + 低幅度色度噪声 + 微小低频色斑；噪声在暗部增强、灯光处减弱。
4. **模拟信号缺陷**：极轻的水平色度拖尾/色度低通，稀少的扫描行不稳定或横向扰动。
5. **光学与采样**：适度锐度降低、细微灯光 bloom、轻暗角；避免二次 gamma 和重复 tone mapping。
6. **独立 HUD**：REC/时间戳/电量等可选，叠在最终画面之上，避免被场景噪声污染；默认不强制开启。

## 3. 可调参数（初始建议，不是物理测量值）

以下统一以 0–1 归一化滑杆表达，Codex 应根据实际 shader 单位重新标定，保留 `off / subtle / reference / degraded` 四档：

| 参数 | reference 初始值 | 说明 |
|---|---:|---|
| overallStrength | 0.55 | 总效果权重 |
| saturationReduction | 0.22 | 适度去饱和 |
| greenShadowBias | 0.12 | 仅阴影偏脏绿 |
| warmHighlightBias | 0.05 | 远处暖光保留 |
| liftedBlack | 0.035 | 极轻黑位抬升 |
| lumaNoise | 0.25 | 暗部细颗粒 |
| chromaNoise | 0.10 | 暗部色斑，低于亮度噪声 |
| noiseTemporalSpeed | 0.35 | 稳定帧率无关时间驱动 |
| chromaBleed | 0.12 | 轻微水平色彩拖尾 |
| horizontalJitter | 0.025 | 低概率小幅扰动 |
| scanlineVisibility | 0.015 | 几乎不可见，不要明显黑条 |
| softness | 0.12 | 轻微软化 |
| highlightBloom | 0.08 | 仅灯具附近 |
| vignette | 0.10 | 克制暗角 |
| glitchFrequency | 0.005 | 默认几乎不触发 |

**约束**：默认禁止大幅画面撕裂、持续 RGB 错位、强烈 CRT 曲面、粗黑扫描线、全屏闪烁和过曝红色滤镜。这些应另建剧情事件预设，不能混进基础录像质感。

## 4. Shader 实现要点

- 使用基于时间和屏幕坐标的可复现伪随机噪声，避免完全固定的纹理，也避免每帧无规律的大幅闪烁。
- 噪声权重按画面亮度变化：`noiseWeight = pow(1.0 - smoothstep(shadowStart, shadowEnd, luminance), shadowPower)`；注意输入亮度与色彩空间一致。
- 亮度噪声以高频小颗粒为主；色度噪声更低频、幅度更小；加入非常微弱的空间相关性，而不是三个 RGB 通道独立强随机。
- 色度扩散优先在 YCbCr/YUV 近似分离后处理色度，尽量保留亮度边缘。避免粗暴对 RGB 三通道做明显位移。
- 轻度横向波动仅作用少数扫描行、幅度很小；故障事件可以单独触发，基础画面不应一直抖。
- 采用渲染分辨率无关的像素尺度；不同 DPR 和窗口大小下效果强度接近。避免动态分辨率导致噪点尺寸忽大忽小。
- 考虑色盲、光敏与眩晕敏感用户：提供效果总开关、颗粒强度和画面抖动独立关闭选项；不要设计高频强闪。

## 5. 必须进行的画面对比

使用用户给出的走廊参考图，建立同类机位测试：长直走廊、低矮吊顶、冷白荧光灯、远端微暖门缝、深暗侧门。输出：

- A：无后处理原图
- B：只调色
- C：调色 + 暗部噪声
- D：完整基础 VHS 质感
- E：同一配置下的明亮房间（检验是否过脏）

以并排截图验收：**暗部有颗粒但仍能辨认通道；灯具仍呈冷白而非纯绿；门后暖光清晰；画面不持续跳动；色彩不被强行洗成统一绿色；玩家能正常观察互动物件。**

## 6. 验收标准

- [ ] 与参考图相比，整体呈低饱和脏灰绿、冷白灯、微暖远端亮区的关系。
- [ ] 噪声主要集中在暗部，亮区较干净，颗粒细而自然。
- [ ] 有轻微视频色度损失，但无夸张 RGB 分离和粗扫描线。
- [ ] 画面保留空间深度、轮廓和可玩性，不因滤镜过暗导致迷路。
- [ ] UI 与场景后处理分层正确，REC/日期可单独开关。
- [ ] 支持强度预设和用户设置；关闭效果时不改变基础场景颜色。
- [ ] 目标平台运行流畅；报告 GPU 开销及是否增加额外全屏 pass。
- [ ] 现有场景、地图、事件、交互和种子复现没有回归问题。
